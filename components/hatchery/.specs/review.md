# AI Code Review 指导规范

> 本文件指导 AI 进行代码审查时关注的维度和标准。

---

## 审查维度

### 1. 正确性

- 逻辑是否正确，边界条件是否处理
- 错误处理是否完善
- 并发安全性

### 2. 安全性

- 是否存在注入风险（SQL、命令、XSS）
- 权限检查是否到位
- 是否泄露敏感信息
- 是否使用了禁止的接口（裸 SQL、直接 New SDK Client）

### 3. 规范性

- 是否遵循 CLAUDE.md 和 `.codebuddy/rules/code.md` 的规定
- 写接口是否有审计日志
- 数据库变更是否双维护（model + sql/ + MigrateFromSQLite）
- API 变更是否更新了 `docs/API.md`
- 日志规范：HTTP handler 中是否使用 `controller.Logger(ctx)`；SDK 调用是否通过 `CallSDKAPITyped` 包装（见 `docs/ops/logging.md`）
- 单测是否按 `docs/testing.md` 规范管理 DB 句柄和异步任务

### 4. 可维护性

- 函数是否过长（>80 行需关注）
- 命名是否清晰
- 是否有不必要的复杂度
- 重复代码是否应抽取复用（不要为了微小差异实现一个新函数，优先复用已有实现）

### 5. 性能

- 是否有 N+1 查询
- 是否有不必要的数据库调用
- 是否有潜在的 goroutine 泄漏

---

## 严重度分级

| 级别 | 说明 | 处理 |
|------|------|------|
| 高 | 安全漏洞、数据丢失、功能错误 | 必须修复 |
| 中 | 性能问题、规范违反、可维护性差 | 建议修复 |
| 低 | 代码风格、命名建议 | 可选修复 |

---

## 红线（自动 REJECT）

触发以下任一条即自动标记为不通过：

1. 使用裸 SQL 接口
2. 写接口无审计日志
3. 修改 model 未同步 sql/ 或 `MigrateFromSQLite`
4. 破坏公共 API 兼容性
5. 硬编码密钥/密码
6. 使用 `model.DB` 而非 `model.DB(r.Context())`
7. 用户可见文案硬编码中文而非使用 `i18n.T()`
8. 新增 `i18n.Key` 未在 `en.go` 添加英文翻译
9. 新增 API 接口或参数但集成测试未覆盖
