# 01. Clarify — 需求澄清

## 背景

客户会根据 VPC/子网组合动态选择“环境”“业务”等腾讯云标签。现有 ClawPro 只能由管理员预先配置全局或分组默认标签，交叉组合会迫使管理员创建大量分组并重复维护成员。

TAPD 要求用户端 `POST /openclaw/create` 和管控端 `POST /admin/instances/create` 都能在单次创建请求中自由指定多个标签；若实例同时命中默认标签，则最终创建请求包含自定义标签和默认标签。

## 目标

- [x] 两个创建接口都新增可选 `tags` 参数，支持多个 `key/value` 标签。
- [x] 自定义标签与命中的全局/分组默认标签合并后写入 CVM `RunInstances.TagSpecification`。
- [x] 同 key 时自定义标签优先，避免重复 key 并保留调用方本次创建意图。
- [x] 标签必须属于 ClawPro 绑定的腾讯云账号，且遵循 RunInstances 的标签约束。
- [x] 不传 `tags` 时保持现有创建与默认标签行为不变。
- [x] 补全 `docs/API.md` 中两个创建接口的参数和合并语义。

## 范围

| 包含 | 不包含 |
|------|--------|
| 用户端 form 参数 `tags`（JSON 数组字符串） | 用户端或管控端前端改造 |
| 管控端 JSON 参数 `tags`（对象数组） | 新增标签选择/查询接口 |
| 默认标签与自定义标签合并 | 修改默认标签管理模型和数据库 |
| RunInstances 请求注入与错误透传 | 在 Hatchery 再实现一套腾讯云标签规则 |
| UT、API 文档、无计费 IT 参数校验 | 创建真实计费 CVM 的自动化验收 |

## 待确认问题

| # | 问题 | 状态 | 结论 |
|---|------|------|------|
| 1 | 两个不同 Content-Type 的接口如何保持同一参数语义？ | 已确认 | 都命名为 `tags`；用户端传 JSON 数组字符串，管控端传对象数组，进入共享流程前统一为同一结构。 |
| 2 | 是否需要先调用 Tag API 验证标签存在？ | 已确认 | 不额外调用。腾讯云官方 RunInstances 契约要求 Tag 来源于 DescribeTags，最终由 RunInstances 对账号归属和完整约束做权威校验并返回原生错误。 |
| 3 | 自定义标签和默认标签同 key 时如何处理？ | 已确认 | 自定义标签优先；相同 key 的默认标签不再追加。 |
| 4 | 自定义标签内部出现重复 key 怎么处理？ | 已确认 | 不静默去重或改值，原样交给 RunInstances 校验，保持云端规则一致。 |
| 5 | 是否需要数据上报？ | 已确认 | TAPD 未给出具体上报字段，本次只扩展既有创建接口，不新增独立事件。既有创建审计链路保持不变。 |

## 约束与依赖

- 用户端继续使用 `application/x-www-form-urlencoded`，管理员端继续使用严格 `application/json`。
- 管理员端 `DisallowUnknownFields` 也应覆盖 `tags[]` 未知字段。
- 标签内容不得写入新增的结构化日志；现有审计只记录创建动作。
- 不修改公共响应契约，不传新参数时完全向后兼容。
- 腾讯云 RunInstances 和 Tag/TagSpecification 是标签约束的权威来源。
