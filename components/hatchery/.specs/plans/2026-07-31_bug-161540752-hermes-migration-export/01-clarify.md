# 01. Clarify — 需求澄清

## 背景与证据

TAPD 缺陷 `161540752` 描述了两个问题：

1. Hermes 在开启 Agent 面板时，迁移导出停在打包阶段，无法上传迁移包。
2. Hermes 实例迁移缺少明确日志，现网失败难以排查。

缺陷截图中的真实终端输出为：

```text
>>> 打包 agent 目录...
tar: .hermes: file changed as we read it
>>> 打包中... 58M 已写入
<脚本直接返回 shell>
```

关闭 Agent 面板后执行同一脚本，打包、分块上传及确认上传均成功。

当前 `scripts/export_migration.sh` 在后台运行 tar，随后直接执行 `wait $TAR_PID`。脚本启用了 `set -euo pipefail`，GNU tar 发现归档根目录元数据在遍历期间变化时返回状态码 1，导致脚本立即退出。Hermes Dashboard 会持续写入 `~/.hermes/logs` 或创建/删除锁文件；即使这些路径已排除，目录项变化仍可能更新 `.hermes` 自身元数据。

## 当前行为与期望差异

| 场景 | 当前行为 | 期望行为 |
|------|---------|---------|
| Agent 面板活跃，仅 `.hermes` 根目录元数据变化 | tar 返回 1，导出中断 | 归档可读时继续上传 |
| 普通配置/数据文件在打包中变化 | 无分类，统一中断 | 继续中断，避免上传不一致数据 |
| 归档损坏 | 仅依赖 tar 退出状态 | 明确验包并失败 |
| 任意导出失败 | 终端可能只有一行 tar 输出 | 打印失败阶段/退出码/日志路径，并保留日志 |

## 目标与验收标准

- [ ] Agent 面板保持打开时，只有 `.hermes` 根目录 changed 告警、未排除业务树指纹一致且归档完整，迁移导出可以继续完成。
- [x] 普通文件 changed、权限、缺失或 tar fatal 错误仍中断，不得上传。
- [x] 根目录业务项或嵌套业务文件在打包期间新增、删除、修改或替换时中断，不得上传。
- [x] 根目录告警兼容只对 Hermes 运行时开启，不改变 OpenClaw/LightClaw ACE 的失败语义。
- [x] 放行任何非零 tar 状态前必须验证归档可读。
- [x] 导出全阶段日志持久化到 agent `logs/`，终端同步显示。
- [x] 失败日志明确包含阶段、退出码与日志路径，且不记录 SMH token、header、分块 URL。
- [x] 共用脚本状态码 0 的既有成功路径不回归。

第一项需要真实 Hermes Agent 面板与 SMH 环境验收，当前以被排除根级锁文件持续变化的可执行
脚本测试替代，未将真实端到端场景标记为完成。

## 范围

| 包含 | 不包含 |

| 按 `.specs/review.md` 完成审查 | 改造尚未合入 master 的 acli 迁移分支 |

## 约束与依赖

- 当前线上截图使用 legacy `.tgz` 导出流程，修复基于 `master`。
- 现网可能使用 GNU tar 1.30 等旧版本；不能只依赖 GNU tar 1.35 对 `--ignore-failed-read` 的新语义。
- `logs` 已在三种内置 Agent 的导出排除列表中，可作为持久化日志位置。
- 本次无数据库、路由、请求或响应字段变化。

## 粒度结论

M 级：单模块脚本行为变化，影响实例迁移可用性，但不改变 API、数据模型、权限或云资源生命周期。
