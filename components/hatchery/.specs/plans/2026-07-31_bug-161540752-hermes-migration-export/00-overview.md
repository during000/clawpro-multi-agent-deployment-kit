## 关键决策备忘

- TAPD 161540752 的失败截图明确显示 `tar: .hermes: file changed as we read it`，脚本因 `set -e` 在 `wait $TAR_PID` 后直接退出。
- Hermes Dashboard 持续写入已排除的 `logs`/锁文件，仍会改变 `.hermes` 根目录元数据；这是归档根目录的易变元数据告警，不等于归档不可读。
- 兼容只对 Hermes 运行时类型开启；OpenClaw、LightClaw ACE 以及其他运行时继续拒绝根目录 changed 状态 1。
- 只容忍“状态码为 1，诊断仅为归档根目录 changed，且打包前后未排除业务树指纹一致”的情况；普通文件变化、缺失、权限或 fatal 错误继续失败。
- 容忍告警后必须执行归档完整性校验，校验失败不得上传。
- 不依赖 GNU tar 1.35 才完善的 `--ignore-failed-read` 行为，兼容现网 Ubuntu 旧版本 tar。
- 导出脚本全程写入 `<agent_home>/logs/migration_export_*.log`，失败时打印阶段、退出码和日志路径；不写入凭证/上传 URL。
- 不停止 Hermes Gateway/Dashboard，避免修复引入用户可见停机。
- 集成测试的 export 请求关闭响应帧输出，避免脚本中临时 SMH 凭证进入 CI 日志；测试结束主动删除创建的 Hermes 实例。

## 风险速览

| # | 风险 | 严重度 | 缓解 |
|---|------|-------|------|
| 1 | 误把普通文件内容变化当作根目录元数据告警放过 | 高 | 仅 Hermes 可进入兼容分支；前后业务树指纹必须一致，且其他诊断仍失败 |
| 2 | 状态码 1 的归档实际损坏 | 高 | 放行前强制 `tar tf` 完整性校验 |
| 3 | 日志记录泄漏 SMH 凭证 | 高 | 仅记录阶段/状态/HTTP 码，不输出环境变量、URL 或 header |
| 4 | 新日志自身触发 tar 变化 | 中 | 日志写入所有类型均已排除的 `logs/`，并在打包前创建 |
| 5 | 旧版 GNU tar 选项语义不一致 | 中 | 不依赖版本相关选项，显式检查退出码与 stderr |
