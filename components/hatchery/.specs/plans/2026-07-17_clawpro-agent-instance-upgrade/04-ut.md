## UT 发现并修复

1. CVM 与 CBS 返回的系统盘容量不一致时，原实现会直接采用 CBS 容量继续执行；现已在 quota/规格询价/write 前以 `disk_not_ready` 保守拒绝。
2. RequestId 落库前的 `DescribeInstances` 读取失败原先会复用并增加无痕迹观察计数；现已拆分读取重试调度，读取失败不消费“三次成功观察”阈值。
3. 新增的 `MsgAdjustmentReasonInstanceNotFound` 与已有 `MsgInstanceNotFound` 中文值重复；现复用已有 Key，`TestI18n_StringUniqueness` 恢复通过。
4. 为测试现有 status 接口的兼容响应，提取可注入 fetcher 的内部 handler；公开路由和行为未变。

## 覆盖率

使用 focused profile：

```bash
go test ./controller ./model ./task \
  -coverprofile=coverage-adjustment.out -covermode=atomic \
  -coverpkg=./controller,./model,./task \
  -run '<上述 feature test regex>' -count=1
```

对多个 test binary 产生的重复 block 按“相同 path + 区间取最大 count”去重，算法与 `.ci/ci-check-coverage.sh` 一致：

## 未覆盖行与残余验证

- 真实腾讯云账号下的库存、余额、未支付订单、可用区 SELL 差异和真实 RequestId 回传时序不在 UT 访问范围；按 Plan 留给 IT。
- MySQL `GET_LOCK` 的跨副本串行性无法在 SQLite UT 中执行；UT 已覆盖 key 的 `UIN+region+action` 隔离、action QPS 和无 burst cadence，真实多副本锁留给 IT。
- CBS/CVM SDK 的 typed request/response 已通过本地 TLS mock server 覆盖；现有 CommonRequest `DescribeInstancesDeniedActions` 的真实账号权限差异仍由 IT 验证。失败路径在 fake-cloud UT 中保证规格分支回退必选 InquiryPrice、系统盘分支继续本地规则。
- `sql/init.sql` 与增量 migration 的 MySQL 实际 DDL 执行不使用 SQLite 假装验证；UT 覆盖 GORM AutoMigrate 的字段、默认值和索引，MySQL DDL 在 IT 部署阶段验证。
- 全量 race 的失败涉及仓库既有全局 DB/全局 hook 测试竞态，失败栈未命中本功能文件；本功能 focused race 与涉及包非 race 全量均通过。该仓库基线问题需独立治理，不在本需求中扩张修改。
- 官方增量覆盖脚本必须在变更 commit 后才能识别 `origin/master...HEAD` 差异；Commit/CI 阶段需再次执行并以其报告作为最终增量门禁。

## 2026-07-22 UT 契约修订

- U10/U11：系统盘合法容量和 online/offline 模式由本地规则生成 operation，询价调用数必须为 0。
- SDK contract：规格升配仍比较 Inquiry/Reset；系统盘只断言 `ResizeInstanceDisks` 的 InstanceId、DiskId、DiskSize、ForceStop 和 ResizeOnline。
- U24/U40：系统盘 worker JIT 不询价，并只执行一次规范化写 operation。
- 新增在线写同步拒绝到 `online_resize_not_supported` 的错误映射测试。
