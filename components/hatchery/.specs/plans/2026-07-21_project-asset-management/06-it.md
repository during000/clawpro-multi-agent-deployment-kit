### 产品 demo 对照与遗漏

`openclaw-enterprise` 的 `feature/admin-asset-management` 分支中，`client/src/pages/admin/project-assets/` 完全基于 `projectAssetStore` 和各工具库 Store，未调用 Hatchery API。其 demo 设计覆盖五类资产：公共技能、企业技能、企业插件、企业 MCP、企业规范；还包含资产版本快照/漂移提醒、更新记录和 `initial` / `autoSync` 同步模式。

当前后端的明确本期范围只有企业技能和企业规范，且项目是扁平结构。因此需要在后续“资产更新记录与同步下发”变更中补齐或明确不做：

1. **真实前端接入**：项目/分组树、成员、资产详情/候选/保存、项目/分组本地 Agent 列表均需改用 API，移除 localStorage mock 作为业务真相源。
2. **资产类型扩展**：公共技能、插件、MCP 尚无对应 `asset_*` 类型、候选、详情、绑定和下发实现；不能让 demo 暗示它们已可用。
3. **版本与更新记录**：后端 `current_version` 当前固定为 `0`，没有资产绑定版本快照、差异、操作人、更新记录或自动同步记录。
4. **同步策略**：demo 的 `initial` / `autoSync` 目前没有后端字段、接口或下发策略；本地 Agent 当前只在 report/sync 时按绑定资产差集生成命令。
5. **实例视图口径**：demo 期望统一展示组织/项目的 Agent；本期接口按用户级分组本地 Agent与 Workspace 项目本地 Agent 分开，且刻意不包含云端 CVM。前端必须据此调整，而不是沿用 demo 的混合实例口径。

- 执行时间：2026-07-16 19:17 ~ 19:20（Asia/Shanghai）。
- 部署环境：用户提供的测试环境 `http://43.144.11.237/api`。
- 鉴权：`Authorization: Bearer <已脱敏管理员 API Token>`；所有请求均通过公网 nginx 的 `/api` 前缀转发。
- 数据隔离：使用两个带时间戳的临时项目；用例结束前已删除。对既有技能和规范的范围变更也在结束前恢复为原始 `all` 状态。
- 工具：`curl` + `jq`；请求与响应体均记录为脱敏摘要，不保存口令、Token 或 Cookie。
