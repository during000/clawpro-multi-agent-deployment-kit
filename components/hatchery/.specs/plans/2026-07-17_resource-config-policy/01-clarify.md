## 背景

当前实例创建主要以站点 `CVMTemplate` 作为腾讯云 `RunInstances` 请求的基础模板。现分支已经实现了一版 `resource_config`：支持站点级资源配置、用户组策略、创建参数覆盖、腾讯云机型/系统盘选项查询及创建前可售性校验。

该首版实现已经以提交 `ceaa1a65` 推送，但项目现要求所有 AI 开发遵循 `CODEBUDDY.md` SOP，且用户明确表示需求已经发生变化。因此本任务需要：

1. 先重新确认最终产品行为和边界；
2. 再将最终需求与当前代码逐项对比；
3. 只在用户确认后进入 Plan；
4. 补齐真实的 Plan、实现记录、UT、Docs、IT、Review 和 Commit 产物。

原始完整产品设计附件 `local://tapd-134207281-backend-resource-policy.md` 当前不可访问；可访问的旧实现计划仅作为历史参考，不作为变更后需求的权威来源。

## 当前代码现状（不是最终需求）

- 站点 `ResourceConfig` 与 `CVMTemplate` 并存；站点配置为空时从模板提取。
- 用户组解析只取“最近一个命中的组策略”，不会把站点和多级祖先做字段级合并。
- 命中组策略后，该 JSON 直接覆盖 `CVMTemplate` 中它明确提供的字段；组策略未提供的字段实际回退到 `CVMTemplate`，而不是站点显式 `ResourceConfig`。
- 普通创建请求当前可传完整 `resource_config` 做最后一层覆盖，另有旧的 `disk_type` 参数冲突校验。
- 动态机型选项当前受固定实例规格 allowlist 限制；系统盘也受后端磁盘类型 allowlist 限制。
- 创建前动态预检当前采用 fail closed，并且在安全组选择/扩容前执行。
- 当前创建路径没有按 `AIImage.ImageSize` 校验最终磁盘容量；它会把小于固定 `MinSystemDiskSize` 的容量静默扩大，这与新确认行为不符。
- 当前只实现后端、迁移和单元测试，没有把前端页面作为已交付范围。

## 最终确认的目标产品

### 1. 管理员可配置平台默认资源规格

平台管理员能够独立于通用 `CVMTemplate` 管理实例资源相关字段：

- 计费模式：`instance_charge_type`
- 包年包月参数：`instance_charge_prepaid.period`、`renew_flag`
- 实例规格：`instance_type`
- 系统盘：`system_disk.disk_type`、`disk_size`
- 公网配置：`internet_accessible.public_ip_assigned`、`internet_charge_type`、`internet_max_bandwidth_out`

预期通过专用管理 API 读取、校验和更新；写操作需要管理员权限和审计记录。`CVMTemplate` 仍负责其他 CVM 参数，`resource_config` 不应反向重写整个模板。

### 2. 用户组可配置资源策略并按最近祖先继承

管理员可为用户组设置 `resource_config` 策略。创建实例时沿当前组到祖先组查找，最近一个命中的组策略生效。

保持首版语义，不做站点和多级祖先的字段级合并：

- 命中组策略时，该策略明确提供的字段覆盖 `CVMTemplate`，未提供字段保留 `CVMTemplate` 值；
- 命中组策略后，不再叠加站点显式 `ResourceConfig`；
- 没有任何组策略命中时，站点 `ResourceConfig` 覆盖 `CVMTemplate`；
- 站点 `ResourceConfig` 为空时，从 `CVMTemplate` 提取兼容配置。

### 3. 创建实例时形成确定的配置优先级

最终确认的优先级是：

```text
CVMTemplate 基础请求
< 最近命中的用户组 resource_config（无命中时使用站点 resource_config）
< 本次创建请求的完整 resource_config 覆盖
< 兼容参数 disk_type（与 resource_config 冲突时拒绝）
< 后端运行时强制字段（镜像、可用区、VPC、子网、安全组、名称、CAM Role）
```

最终 `RunInstancesRequest` 是合并后的唯一结果。后端运行时安全字段不能被站点、组策略或客户端 JSON 覆盖。

普通用户继续允许通过创建请求提交完整 `resource_config`；后端执行与管理端相同的结构校验和规范化。

### 已确认的新行为：镜像容量不足时直接失败

- 校验对象是最终选择的镜像 `enabledImage` 和经过站点、组策略、创建参数合并后的最终系统盘容量。
- 当 `enabledImage.ImageSize` 大于最终系统盘容量时，创建接口直接返回失败。
- 失败必须发生在安全组选择/扩容和腾讯云 `RunInstances` 调用之前。
- 后端不得修改用户最终选择的磁盘容量，不得把磁盘静默扩大到镜像大小或固定最小值。
- 错误响应应明确包含“镜像所需容量”和“当前选择容量”，方便用户重新选择。
- 镜像大小等于系统盘大小时允许继续创建。
- 当 `enabledImage.ImageSize == 0` 时，跳过镜像容量比较，保持最终系统盘容量不变并继续调用腾讯云 CVM API，由 CVM 判断镜像与磁盘是否兼容。

### 4. 管理端可获取真实可选项

管理端需要用于表单联动的只读选项：

- 静态基础枚举：计费模式、续费方式、公网计费方式、预付费周期；
- 指定地域/可用区和计费模式下可售的实例规格；
- 指定实例规格下可用的系统盘类型及大小范围。

动态数据来自腾讯云 CVM/CBS API，使用 TTL 缓存和同 key 并发去重，`refresh=1` 绕过缓存。保持固定 Ai2 实例规格 allowlist 和系统盘类型 allowlist，不扩展到腾讯云全部机型。

### 5. 保存和创建前使用一致的基础校验

站点保存、用户组策略保存和用户创建参数使用同一套资源配置结构校验和规范化规则：

- 实例规格和系统盘类型符合固定 allowlist；
- 系统盘大小满足平台最低容量；
- 预付费配置与计费模式一致；
- 公网配置组合合法；
- JSON 必须是可解析的单个 object；未知字段兼容忽略，预期字段必须正确解析并通过上述业务校验。

创建前继续通过缓存或腾讯云 CVM API 验证实例规格在目标可用区可售；缓存未命中且云 API 失败时 fail closed。系统盘选项接口提供云端类型和范围，最终磁盘兼容性由 CVM `RunInstances` 判断，但新增以下镜像容量快速失败：

- `ImageSize > 0` 且大于最终系统盘容量：在安全组选择/扩容前直接失败；
- `ImageSize == 0`：跳过镜像容量比较，不修改系统盘容量，继续调用 CVM；
- 所有分支均禁止静默扩大用户最终选择的磁盘容量。

### 6. 保持兼容并可解释生效来源

已有仅依赖 `CVMTemplate` 的站点不应因为新增字段而无法创建实例。读取配置时需要明确来源，例如站点显式配置、从旧模板提取、默认模板或用户组继承，便于管理端展示和排障。

## 验收目标（已确认）

- [ ] 管理员能读取和更新平台默认资源配置，非法组合被拒绝且不落库。
- [ ] 管理员能为用户组设置和删除资源策略，并能看到策略的生效来源。
- [ ] 用户创建实例时，最终 CVM 请求严格遵守确认后的优先级和继承语义。
- [ ] 资源选项接口返回指定可用区下的真实可售机型和系统盘约束，并正确使用缓存。
- [ ] 最终系统盘满足云端范围；镜像大小已知且大于最终系统盘容量时，在创建附属资源前明确失败且不修改容量；镜像大小为 0 时跳过该比较并交由 CVM API 判断。
- [ ] 腾讯云预检失败时按确认后的降级策略处理，不创建安全组等可避免的附属资源。
- [ ] 没有显式 `resource_config` 的历史站点保持原有 `CVMTemplate` 创建行为。
- [ ] 新增/修改 API 有 UT、集成测试、审计和 API 文档覆盖。

## 约束与依赖

- 遵循 `CODEBUDDY.md` 的 Clarify → Plan → Implement → UT → Docs → IT → Review → Commit SOP，每步需要用户明确确认后推进。
- 数据库字段变更必须同时维护 GORM model、`sql/init.sql` 和目标 Release 日期对应的增量 migration。
- 写接口必须使用 `requireAdmin`、`WithAudit` 和审计规则。
- 腾讯云客户端必须通过统一 `GetXxxClient(ctx)` 工厂创建。
- 新增 API/参数必须有集成测试覆盖；新增代码目标覆盖率不低于 80%。
- 不得记录或提交任何腾讯云密钥、admin token 或 kubeconfig 内容。
