## 关键决策备忘

- 只保留原 `GET /admin/audit`，继续同步返回 `total` / `total_pages`；不新增 count 路由、快速模式或缓存。
- 撤回 `username_exact`；`username` 参数默认使用等值查询，既有 API 调用方传完整 username 时请求形式不变且可命中联合索引。
- 仅 `fuzzy=1` 时执行 `username LIKE '%keyword%'`；此前依赖部分 username 的调用方必须显式增加该参数。
- 新前端通过 `/admin/users?fuzzy=1` 获取候选，选中后按 `user_id` 查询 audit；显式模糊 audit 只作为无法选定用户时的兼容能力。
- 接受首页首次进入时执行一次当前租户无 username 条件的 count；该查询可扫描 identifier 覆盖索引。
- TAPD 验收应包含前端选定用户后改传 `user_id` 的联调证据，同时验证既有 API 调用方传完整 username 时无需改变请求形式。

## 风险速览

| # | 风险 | 严重度 | 缓解 |
|---|------|-------|------|
| 1 | 调用方以部分 username 查询但未增加 `fuzzy=1`，结果语义改变 | 高 | 文档明确默认精确；确需模糊的调用方显式增加参数 |
| 2 | 首次无筛选 count 随租户记录数线性增长 | 中 | 仅首次/刷新执行，在预发布监控耗时和 rows examined |
| 3 | 显式 audit `fuzzy=1` 仍可能扫描大量索引项 | 中 | 只作为兼容能力；页面主流程选人后按 user_id 精确查询 |
| 4 | `/admin/users` 模糊候选查询本身偏重 | 中 | 小 page、防抖；如成为瓶颈另立轻量 options 接口 |
| 5 | 三个联合索引增加写入和 DDL 成本 | 低 | 仅增加明确对应 user_id/username/resource_id 查询的租户联合索引，在 MySQL 8 验证迁移 |
