# 01. Clarify — 需求澄清

> AI 以产品经理角色进行 Discovery + Challenge，确保需求清晰、边界明确。

---

## 背景

现有 `POST /openclaw/create` 只能以当前登录用户身份创建 CVM Agent。管控端 Agent 列表缺少管理员代指定用户创建并分配 Agent 的后端能力，也无法在创建请求中一次性声明目标分组、初始模型、多个手动通道和追加技能。

TAPD 需求为 `1020422209135676012`（短 ID `135676012`）：管理员从管控端 Agent 列表创建 Agent，并把 Agent 分配给指定用户；目标用户随后可在用户端查看和管理该 Agent。

## 目标

- [x] 新增管理员专用的 CVM Agent 创建接口，并将实例归属到指定用户。
- [x] 目标用户无有效分组时使用未分组；只有一个有效分组时自动选择；多个有效分组时要求显式指定。
- [x] 创建主逻辑与用户端一致，不复制配额、镜像、网络、安全组、角色和实例落库流程。
- [x] 创建时可指定运行时支持的初始模型；仅 OpenClaw 兼容运行时可指定 fallbacks。
- [x] 创建时可配置多个现有手动通道，并可追加 public/enterprise 技能。
- [x] 模型、通道、技能在 Agent ready 后异步下发，不改变基础 CVM 创建成功语义。
- [x] 管理员不能绕过目标用户/分组的配额、资源状态、能力和可见性边界。
- [x] 通道密钥不得出现在响应、审计或结构化日志中。

## 范围

| 包含 | 不包含 |
|------|--------|
| 新增 `POST /admin/instances/create` JSON API | 管控端前端页面改造 |
| 仅创建 CVM Agent | 本地 Agent 预创建或导入 |
| 指定目标用户和目标分组 | 修改普通用户创建 API 的请求契约 |
| 初始单模型；OpenClaw 兼容运行时支持 primary + fallbacks | 为不支持模型的运行时伪造模型能力 |
| 多个现有手动通道配置 | qrcode、扫码或自动授权通道流程 |
| 追加 public/enterprise 技能 | 替换角色技能或技能包技能 |
| 等待 Agent ready 后异步下发 presets | 新增持久化预设表、查询接口、恢复 worker 或自动重试 |
| API、审计、i18n、单元测试和集成校验脚本 | 新增数据库 schema |

## 待确认问题

| # | 问题 | 状态 | 结论 |
|---|------|------|------|
| 1 | 创建主流程是否应与用户端完全一致？ | 已确认 | 是。抽取共享创建主流程，管理员入口只增加目标用户、分组和 presets。 |
| 2 | 所有 Agent 类型是否都支持 primary + fallbacks？ | 已确认 | 否。支持模型的类型都可指定一个初始模型；仅 OpenClaw 兼容运行时支持 fallbacks，3.28.x 不支持 fallback。 |
| 3 | 通道是否只允许一个？ | 已确认 | 否。支持多个，按请求顺序使用现有手动配置逻辑下发；不支持 qrcode。 |
| 4 | 创建时选择的技能是替换还是追加？ | 已确认 | 追加，不影响角色技能和技能包技能。 |
| 5 | 创建期 presets 是否需要持久化、恢复和重试？ | 已确认 | 不需要。只在当前进程等待 Agent ready 后尝试一次；失败后由管理员使用现有接口重配。 |
| 6 | public 技能是否必须显式传 source？ | 已确认 | 不必；省略或空值时默认 `public`，显式 `enterprise` 走企业技能可见性校验。 |

## 约束与依赖

- 管理员鉴权沿用现有 `requireAdmin` 和审计中间件。
- 用户、分组、配额、模型、通道和技能校验必须在调用 CVM `RunInstances` 前完成。
- 目标分组必须属于目标用户，且不能是 `to_be_deleted`。
- models/channels/skills 必须受 `agent_type` 能力矩阵约束。
- 模型、通道和技能配置必须复用用户端手动操作核心实现，避免两套状态语义。
- Agent ready 检测依赖现有实例状态和轮询机制。
- 通道凭据只允许存在于当前请求和异步 goroutine 内存中。
- 写接口必须包含审计规则、i18n 英文翻译、API 文档、UT 和 IT 校验。
