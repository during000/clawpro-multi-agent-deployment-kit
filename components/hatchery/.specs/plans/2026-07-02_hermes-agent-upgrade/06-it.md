# IT（本次补齐）

## 缺口

原分支只有 `test/scripts/openclaw_instance/test_instance_upgrade.py` 一份通用契约测试，不区分 `agent_type`，无法验证：
1. `/admin/agent-types` 返回的 `hermes.supports_upgrade` 确实为 `true`；
2. Hermes 类型实例调用升级接口时，能正确穿过 `checkInstanceSupportsUpgrade` 类型校验（而不是被误拒绝）；
3. 契约层（参数校验/鉴权/状态拒绝）对 Hermes 实例同样成立。

对比同项目其它模块（channel/model 等）均有专属 `*_hermes.py` 测试文件，升级链路此前是唯一的空白。

## 新增文件

`test/scripts/openclaw_instance/test_instance_upgrade_hermes.py`

覆盖 9 个用例：
1. `test_01_hermes_supports_upgrade_flag`：`GET /admin/agent-types` 断言 hermes 条目 `supports_upgrade == true`（核心回归保护点）
2. `test_02_hermes_upgrade_missing_id`：缺 id → 400
3. `test_03_hermes_upgrade_nonexistent_id`：不存在的 id → 4xx
4. `test_04_hermes_upgrade_no_real_trigger`：Hermes 实例升级请求不应被类型校验误拒绝（仅契约级，默认不真实触发升级；`ALLOW_REAL_UPGRADE=1` 时才走真实路径）
5. `test_05_hermes_upgrade_auth`：认证三件套（无认证/错误token/非管理员）
6. `test_06_hermes_upgrade_retry_missing_id`：retry 接口缺 id → 400
7. `test_07_hermes_upgrade_retry_nonexistent_id`：retry 接口不存在的 id → 4xx
8. `test_08_hermes_upgrade_retry_state_reject`：非 `upgrade_failed` 状态调用 retry → 400/409
9. `test_09_hermes_upgrade_retry_auth`：retry 接口认证三件套

## 设计要点

- **不复用跨文件共享实例**（`_shared.py` 的 `require_shared_instance`），因为共享实例默认 `agent_type=openclaw`，无法验证 Hermes 专属能力位；本文件独立创建一个 hermes 实例（`setup_hermes_instance`），创建失败时依赖实例的用例自动 SKIP，不阻塞纯契约用例。
- **绝不在测试中真实触发 Hermes 升级**（重装耗时 15+ 分钟），与 `test_instance_upgrade.py` 保持同样的安全策略，仅在 `ALLOW_REAL_UPGRADE=1` 显式开启时才走 happy path。
- **核心回归点**是 `test_01`：直接断言 `AgentType.SupportsUpgrade` 能力位在 API 层的可见结果，这是本次分支新增能力的直接证据，也是最容易被后续误改回归的点。
