## 关键决策备忘

> **跨阶段共享的关键上下文**。仅记录影响后续步骤的决策，避免恢复时还要翻阅历史阶段文件。

- 三个 `/distribute` 接口新增 `select_all=true`，与现有 `instance_ids` 模式严格二选一。
- 全选按目标版本的资源安装状态和用户分组筛选；空状态表示全部允许稳定状态，过渡状态始终禁止。
- 全选目标不限量且为请求时快照；必须分批查询、分批落库，并在每批内复用现有 semaphore 并发限制。
- 目标能力过滤对齐现有下发 handler，不新增 `running` 限制；多技能逐技能独立解析目标。
- MCP 全选只返回汇总；显式 ID 模式及其现有数量限制保持兼容。
- 批大小固定为 200；全选路径用实例/record 主键 keyset 分页，每批执行完成后再读下一批，执行前先固化全部 task records。
- 人工 Review 后取消跨资源 controller/model 分页抽象：selection、target、keyset 循环和批大小归各资源，`model` 仅保留用户组过滤，执行复用各资源既有 semaphore。
- 技能和插件卸载复用各自全选任务链路，仅接受 `installed/outdated/upgrade_failed/uninstall_failed/uninstall_failed_old`；MCP 无管理员批量卸载接口。
- `search` 仅用于 `select_all=true`，最长 50 个字符，模糊匹配实例名称、云实例 ID 和创建人用户名；显式 `instance_ids` 模式拒绝筛选参数。

## 风险速览

| # | 风险 | 严重度 | 缓解 |
|---|------|-------|------|
| 1 | 不限量全选导致大查询、大事务和海量 goroutine | 高 | 查询/落库/执行均按 200 条分批，批内 semaphore 限制活跃 goroutine |
| 2 | 全选不限制 `running`，可能产生可预见执行失败 | 中 | 明确对齐现有下发行为，在任务记录中保留逐实例结果 |
| 3 | 状态相对版本计算错误导致误选或重复下发 | 高 | 先解析目标版本，复用各资源状态 CASE 并补充边界测试 |
