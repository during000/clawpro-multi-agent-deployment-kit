## 执行命令

```bash
# 本机 GO111MODULE=off，因此所有项目命令显式开启 module 模式。

# 计划用例 + 两个数据库失败分支，race 与定向覆盖率
GO111MODULE=on go test ./controller ./task -v -race \
  -coverprofile=/tmp/clawpro-doctor-targeted.cover \
  -run 'Test(ActivateDoctorSession_(成功激活|激活状态写入失败)|RefreshDoctorSTS_(刷新即将过期的密钥|过期时间写入失败)|CleanupDoctorSessions_(Active未超时则跳过|无文件超时则结束|无文件未超时则跳过|无文件存量会话按创建时间超时))$' \
  -count=1

# Doctor 模块相关完整回归
GO111MODULE=on go test ./controller ./task -race \
  -run 'Doctor|RefreshDoctorSTS|CleanupDoctorSessions' -count=1

# 全仓 race
GO111MODULE=on go test ./... -v -race

# 项目规定的增量覆盖率脚本
GO111MODULE=on BASE_BRANCH=master bash .ci/ci-check-coverage.sh

# 工作区实际变更的覆盖 profile（脚本只比较 HEAD，无法识别未提交改动）
GO111MODULE=on go test ./controller ./task \
  -coverprofile=/tmp/clawpro-doctor-incremental.cover \
  -covermode=atomic -coverpkg=./... \
  -run 'Test(ActivateDoctorSession_(成功激活|激活状态写入失败)|RefreshDoctorSTS_(刷新即将过期的密钥|过期时间写入失败)|CleanupDoctorSessions_(Active未超时则跳过|无文件超时则结束|无文件未超时则跳过|无文件存量会话按创建时间超时))$' \
  -count=1
```

## 全仓检查说明

`GO111MODULE=on go test ./... -v -race` 未全量通过，失败来自未修改的既有用例：

- 用例：`TestCheckAllAgents_SecureFirstBootTriggered_CustomImage`
- 原因：`checkAllAgents` 启动的后台 goroutine 尚未退出时，测试 cleanup 调用
  `model.UseDBForTest.func1` 恢复全局 DB，触发 data race。
- 相关文件：`task/agent_checker.go`、`task/secure_first_boot_test.go`、`model/db.go`。
- `git diff origin/master` 确认以上三个文件在本分支均无改动。
- 本次 Doctor 目标用例独立执行 `-race` 全部通过，因此该既有 race 不影响本修复的测试结论。

测试日志中 NoFiles 超时用例还会输出 `audit_logs` 表不存在，但审计写入为
best-effort，断言正常通过；项目已有 `doctor_cleanup_audit_test.go` 的专用审计夹具覆盖该行为。
