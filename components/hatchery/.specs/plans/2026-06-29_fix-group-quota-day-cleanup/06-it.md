# 06. IT — 集成测试评估

> 评估集成测试与增量 API 覆盖率需求。本次为纯后端 handler 行为修正，不涉及新 API 接口或参数。

---

## IT 影响评估

### 1. 现有 IT 是否受影响

扫描 `test/` 目录（Python 集成测试），**无任何用例命中 `/admin/group-config/policy` 或 `/admin/group-config/policy/delete`**。

`test/` 中涉及 `token_quota_day` / `global_token_quota_day` 的用例均为其他路径：
- `test/scripts/admin_user/test_admin_user_lifecycle.py` — 走 `/admin/create`、`/admin/update-user`（用户级配额，非分组策略）
- `test/scripts/admin_usage/test_admin_usage_data.py` — 只读断言 usage 响应里的 `global_token_quota_day` 字段存在
- `test/scripts/helpers/user_mgmt.py` — 用户创建 helper

**结论：现有 IT 不会因本改动而破坏。**

### 2. 增量 API 覆盖率（红线 #13）

红线 #13：「新增 API 接口或参数但集成测试未覆盖」。

本任务**未新增接口、未新增参数**：
- `POST /admin/group-config/policy` 端点、请求体 schema 不变
- `POST /admin/group-config/policy/delete` 端点、请求体 schema 不变
- OpenAPI spec 无新增 operation / param

因此 `make openapi BASE_BRANCH=origin/master` 对比结果中 `new_ops_uncovered` 与 `new_params` 均为空，**红线 #13 不适用**。

### 3. 是否需要新增 IT 用例

**非必需**（不阻塞合并）：本次改动的外部可观测行为（写 rules 清 day、delete fallback）已由 22 个单元测试覆盖核心路径，且无现有 IT 涉及该端点。

**建议（可选）**：若后续有 K8s 环境可用，可在 `test/scripts/` 下新增一个分组策略 IT 用例，覆盖"set token_quota_rules → 断言 token_quota_day binding 被清理"与"delete token_quota_rules（仅有 day binding）→ 断言 day 被清理"两个回归点。优先级低，单元测试已等价覆盖。

---

## IT 执行

本任务**未执行** `make test IMAGE=...`，原因：
1. 无新 API 接口/参数，增量覆盖率红线不触发
2. 无现有 IT 命中改动端点，无回归风险
3. 单元测试已覆盖全部新增分支（见 04-ut.md）
4. K8s 环境与镜像构建为重型操作，收益与成本不匹配

若 Review 阶段或合并前需要 IT 验证，可执行：
```bash
make openapi BASE_BRANCH=origin/master
make test IMAGE=<镜像> BASE_BRANCH=origin/master TEST_ARGS="--report-dir ./test-report"
```
