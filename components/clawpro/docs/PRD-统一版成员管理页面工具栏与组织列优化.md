## 一、需求背景（价值和目的）

**背景**：用户管理（成员管理）页面在引入「统一版本（unified）」后，沿用了普通 OneID 专用模式的「部门 / 自定义组织」双概念结构。当数据源同步后，「部门」与「自定义组织」本质都归属于同一棵企业组织树（以根组织「A公司」为顶层），双概念的呈现造成以下问题：

- 组织视图左侧树把「部门」「自定义组织」分区展示，割裂了同一组织树；从自定义分组迁移来的组织（如「前端基础架构与工程效能研发协作组」）游离在「A公司」之外，层级关系不清。
- 右侧列表「部门」列与「组织」列并存，语义重叠；组织列 hover 还按「部门 / 自定义分组」来源标注，与统一版「组织」口径不符。
- 「同步部门作为组织」按钮文案与位置、「添加用户到组织」弹窗「所属部门」字段、工具栏「全部部门」筛选与「手动同步」按钮等，均为普通模式残留，统一版语境下语义/视觉不一致。

**目标**：在统一版中把「部门 + 自定义组织」统一收敛为单一「组织」概念，以根组织「A公司」为唯一顶层组织树；同步术语、列结构、工具栏与弹窗文案，使整页围绕「组织」一致呈现。普通 OneID 专用模式保持原样不受影响。

## 二、需求场景

**用户影响**：
- 角色1 · 企业管理员（统一版）：组织视图与全部视图的组织展示、筛选、同步、添加用户等交互全面「组织化」。
- 特意排除：普通 OneID 专用模式（standard，`!isUnified`）—— 部门筛选、角色筛选、用户搜索框、左侧「手动同步」、「部门」列及其「主部门」标识等**全部保持原样**。

**场景 1 · 组织视图左侧树合并（A1 + B1）**
1. 管理员进入 `/admin/members`，切换到「组织」视图。
2. 查看左侧组织树。
3. 系统反应：左侧栏**不再分「部门 / 自定义组织」两个分区**，合并为一棵树；根组织「A公司」为唯一最上层；原从自定义分组迁移来的组织（如「前端基础架构与工程效能研发协作组」）挂到「A公司」下一层级，**与「技术部」并列同级**。
4. 验证：树仅有一个顶层「A公司」；自定义来源组织与部门来源组织在 A公司 下混合并列。

**场景 2 · 组织视图右侧列表删除部门列（A2）**
1. 管理员在「组织」视图选中某组织节点，查看右侧成员/内容列表。
2. 观察列结构。
3. 系统反应：右侧列表**不再展示「部门」列**。
4. 验证：列表无「部门」列。

**场景 3 · 同步入口改造（A3）**
1. 管理员在「组织」视图查看左侧顶部操作区。
2. 观察按钮。
3. 系统反应：原「同步部门作为组织」按钮文案改为**「同步数据源」**，位置移动到**「新建」按钮右侧**；同步进行中显示「同步中...」，完成 toast「已同步数据源」。
4. 验证：按钮文案为「同步数据源」，位于「新建」右侧；点击可触发同步态。

**场景 4 · 组织列 hover 数字化（B2 + C5）**
1. 管理员在「全部」视图查看某用户「组织」列，hover 至单元格。
2. 观察浮层内容。
3. 系统反应：浮层**不再按「部门 / 自定义分组」来源标注**，改为**数字编号列表**（`1.`、`2.` …）逐行展示组织完整路径；**第一条**（主组织路径）后附「主组织」角标。交互参考截图：`1. A公司 / 产品部 / 设计组 [主组织]`、`2. A公司 / 技术部 / 前端架构与跨平台体验设计组`。
4. 验证：浮层为数字编号路径列表，首条带「主组织」角标，无来源分组标签。

**场景 5 · 添加用户弹窗字段改名（B3）**
1. 管理员点击「添加用户到组织」按钮，打开弹窗。
2. 观察弹窗内列。
3. 系统反应：原「所属部门」列改为**「所属组织」**。
4. 验证：弹窗列名为「所属组织」。

**场景 6 · 统一版列结构调整（B4）**
1. 管理员在统一版「全部」视图查看表格表头。
2. 观察列。
3. 系统反应：原「部门」列改为**「组织」列**，并**删除原先单独的「组织」列**（合并为单一「组织」列），列内容沿用组织完整路径（主组织置顶 + 主组织角标）。
4. 验证：表格仅一列「组织」，无重复列。

**场景 7 · 全部视图工具栏与列名（C1 + C2 + C3）**
1. 管理员在统一版「全部」视图查看工具栏与表头。
2. 观察控件。
3. 系统反应：
   - 「组织」列名为纯文字「组织」，**无** hover 信息提示图标；
   - **不展示**「全部部门」下拉筛选；
   - 右端操作区按 `下载 → 添加用户 → 同步` 排列，「手动同步」改名「同步」并置于**最右侧**。
4. 验证：列名无 Info 图标；无部门筛选；同步按钮在最右且文案为「同步」。

**场景 8 · 组织视图工具栏精简（C4）**
1. 管理员在统一版切到「组织」视图，查看顶部工具栏。
2. 观察控件。
3. 系统反应：仅保留「全部 / 组织」分段切换；**不展示**「全部部门」下拉、用户搜索框、同步按钮。
4. 验证：工具栏除分段切换外无其它筛选/搜索/操作控件。

**场景 9 · 普通 OneID 模式回归（反向验证）**
1. 管理员以普通 OneID 专用模式（`!isUnified`）进入页面，遍历全部/组织视图。
2. 系统反应：部门筛选、角色筛选、用户搜索框、左侧「手动同步」、「部门」列与「主部门」标识、组织列来源标注等**全部与改动前一致**。
3. 验证：与改动前完全一致。

## 三、页面设计/前端方案

### 3.1 页面结构

涉及页面：管控端 · 成员管理 `/admin/members`

| 区域 | 组件/文件 | 改造点 |
|------|-----------|--------|
| 组织视图 · 左侧树 | `GroupList.tsx` | 合并「部门/自定义组织」为单树；「同步数据源」按钮置于「新建」右侧 |
| 组织视图 · 数据建模 | `health.ts` | `buildUnifiedGroupTree` / `normalizeGroupsForUnifiedTree`：A公司为唯一顶层，manual 节点 reparent 到根 dept |
| 组织视图 · 右侧列表 | `NodeContentPanel.tsx` / `GroupView.tsx` | 删除「部门」列；「添加用户到组织」弹窗「所属部门」→「所属组织」 |
| 全部视图 · 工具栏 | `MemberManagement.tsx` | 统一版隐藏部门筛选、组织视图隐藏搜索框、同步按钮改名移位 |
| 全部视图 · 表头/单元格 | `MemberManagement.tsx` | 「部门」列→「组织」列并删重复列；列名去 hover；组织列 hover 数字编号 + 主组织角标 |
| 关联选择器 | `PlatformPolicy.tsx` 等 | 应用范围/上级组织选择器复用 `buildUnifiedGroupTree`，A公司唯一顶层，去 source 分区标题 |

### 3.2 交互规则

| 规则 | 控件/对象 | 统一版「全部」 | 统一版「组织」 | 普通 OneID 模式 |
|------|-----------|:--:|:--:|:--:|
| R1 左侧树分区 | 部门/自定义组织划分 | — | 合并单树（A公司唯一顶层） | 保持 |
| R2 自定义来源组织层级 | 迁移组织 parentId | — | reparent 到 A公司 下，与技术部同级 | 保持 |
| R3 右侧列表「部门」列 | 列 | —（见 R10） | 删除 | 保持 |
| R4 同步按钮文案 | 「同步数据源」 | —（见 R9） | 「同步数据源」 | 「手动同步」 |
| R5 同步按钮位置 | 左侧顶部 | — | 「新建」右侧 | 工具栏左端原位 |
| R6 组织列 hover | 浮层内容 | 数字编号路径 + 首条「主组织」 | — | 来源标注（保持） |
| R7 添加用户弹窗字段 | 「所属组织」 | 所属组织 | 所属组织 | 所属部门（保持） |
| R8 列名 hover 提示 | 「组织」列名 | 移除（纯文字） | — | 保持 |
| R9 同步按钮（工具栏） | 文案/位置 | 「同步」/ 右端最右 | 移除 | 「手动同步」/ 左端 |
| R10 「全部部门」下拉 | 筛选 | 移除 | 移除 | 保持 |
| R11 用户搜索框 | 搜索用户 ID | 保留 | 移除 | 保持 |
| R12 列结构 | 部门列/组织列 | 「部门」列→「组织」列并删重复「组织」列 | — | 保持双列 |

判定口径（前端布尔条件）：
- 左侧树：组织视图统一调用 `buildUnifiedGroupTree(visibleGroups)`，输出以 `dept-root`（A公司）为唯一顶层、part(`oneid-dept`) 与 manual 合并的单棵树。
- 部门筛选：`hasOneid && !isUnified` 才渲染「全部部门」下拉。
- 用户搜索框：`!(isUnified && viewMode === "group")` 才渲染。
- 工具栏同步：左侧旧按钮 `hasOneid && !isUnified`；右端新「同步」按钮 `isUnified && viewMode === "all"`，置于操作区末尾。
- 列名/列结构/主组织角标：仅 `hasOneid && isUnified` 分支生效。

### 3.3 展示状态

- 正常态：按上表渲染对应控件、列与文案。
- 空态：组织树无数据显示「暂无组织」；组织列无数据显示「—」。
- 同步中态：同步按钮显示「同步中...」+ loading 图标并禁用，完成 toast 提示。
- 视图切换：「全部 ↔ 组织」切换时工具栏控件按 R9~R11 即时增减。

## 四、后端方案

本需求为**纯前端 UI/交互 + 前端构树建模**调整：组织树合并、A公司唯一顶层（`parentId` 重映射仅作用于构树副本，不污染源数据）均在前端完成。**不涉及任何后端 API 改动、数据库结构变更或权限逻辑变更**；同步沿用既有 `handleSync` / `onDeptSyncedChange` 模拟逻辑。

================================================================

## 五、边界条件

### 数量边界
- 不变更列表数量与分页上限（管控端 page_size 默认 20 / max 100，用户端 30/页）。
- 组织树多路径用户：组织列 hover 浮层逐条数字编号展示，无条数硬上限（沿用现状滚动）。

### 时间边界
- 同步操作沿用 `isSyncing` / `isSyncingDepts` 进行中态，无新增超时/节流。

### 并发与异常
- 同步进行中按钮置灰禁用，防重复触发。
- `parentId` 重映射只改写构树副本，避免污染源数组导致跨页面选择器数据错乱。
- 模式/视图判定为纯前端条件组合，无并发风险。

## 七、待研发 TL 确认

- Q1：组织树合并依赖根组织 `dept-root`（A公司）存在；当数据源尚未同步、无 `oneid-dept` 根时，是否退化为原扁平展示？预期空态文案？

- Q4：组织列「主组织」角标对应「主部门」语义来源（`isPrimary`），多组织用户是否始终存在且唯一一个主组织？无主组织时的展示？
