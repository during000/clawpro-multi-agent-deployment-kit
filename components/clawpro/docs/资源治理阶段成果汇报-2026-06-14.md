## 一、一句话成果

> 这一轮对 ClawPro 全项目图标与图片资源做了一次系统性治理：**全量扫描盘点 1002 项资源、建立 1509 处引用映射**，在严守品牌/渠道/头像红线、零误删的前提下**清理 137 个重复冗余文件（回收约 928 KB）**，把 **746 项待确认、206 处引用告警**全部核查处置闭环，并沉淀出 **14 个 canonical 统一入口**、一个可浏览的资源库单页和一套可重复执行的"扫描→分类→去重→治理"脚本链路，让资源治理从一次性动作升级为可持续机制。

---

## 二、背景与目标

项目内图标/图片资源长期散落在多个目录（`client/public/assets`、`client/public/icon`、`client/src/assets`、根 `icon`、根 `assets` Figma 导出等），存在大量重复副本、来源不清、引用关系不明的问题。本轮目标：

1. 盘清家底——全量扫描所有图标/图片资源及其引用关系。
2. 去重瘦身——在不误删、可回滚的前提下清理重复冗余资源。
3. 建立机制——沉淀 canonical 统一入口、资源库单页、组件资源映射与可重复脚本，支撑后续持续治理与 AI/vibe coding 选图。

严守硬边界：不做私有 npm 包、不做全量资源迁移、不做强注册体系、不做在线上传/删除/SVG 编辑、不做全量组件重构、不擅自改组件源码。

## 五、红线与安全（治理的可信度保障）

本轮治理最大的特点是**破坏性动作（删除）全程可控、可审计、可回滚**：

- **逐候选独立现场复核**：每个待删文件都要同时满足"零引用线索 + 同组 canonical 在场 + 字节完全一致"才删，任一不过即跳过转待确认。
- **红线绝不自动归并**：品牌 Logo、渠道图标、Agent 头像即便字节一致也强制进 C 类人工确认，杜绝把企业微信/企业微信应用等品牌资源错误合并。
- **事实源永不删**：registry 已登记的资产源文件即便不是 canonical 也保留。
- **全程 git 跟踪**：137 个删除全部可逐个回滚（`git checkout`）。
- **页面零风险**：资源库单页只消费静态 JSON，不在线扫描/上传/删除/编辑文件。

## 七、价值与后续

**已交付价值：**
1. **盘清家底**——1002 项资源 + 1509 处引用第一次有了完整账本，资源现状可查。
2. **去重瘦身**——137 个重复冗余文件清理，回收约 928 KB，且零误删、可回滚。
3. **建立机制**——14 个 canonical 入口实现"改一处全局生效"，加可重复脚本链路 + 资源库单页 + 组件映射；并产出**组件资源自检脚本**（`npm run check:component-resources`，带退出码与基线机制，当前为手动执行、具备接入 CI/pre-commit 的条件），为把治理从"一次性清存量"延伸到"防新增倒退"打好基础，治理可持续。

**后续待推进（阶段 9–11）：**
- 阶段 9：skill 连接，让 AI/vibe coding 按上下文稳定选图（lucide / canonical / 宿主注入）。
- 阶段 10–11：安全校验、回归检查与落成验收。
- 长期项：keep-multiple 双份资源一致性校验；待确认资源经设计确认后增量纳入 canonical。
