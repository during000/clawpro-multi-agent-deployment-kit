# 需求单：Skill 更新 / 下载 / 删除


---

## 一、需求背景

企业技能库已完成 Skill **上传入库**（ZIP 解析 + SKILL.md 自动提取）、**分类管理**、**批量下发**、**下发进度追踪** 等核心能力。但在实际运营中存在以下痛点：

1. **无法就地更新**——Skill 迭代新版只能删除重传，丢失下发记录等历史数据。编辑按钮 Tooltip 已预留提示"近期会上线更新功能"。
2. **无法导出下载**——管理员无法将已入库 Skill 导出为 ZIP，不便跨环境迁移或本地审查。
3. **无法删除单个 Skill**——废弃或误传的 Skill 永久留存，影响管理效率。

---

## 二、需求目标

| 编号 | 能力 | 一句话描述 | 优先级 |
|------|------|-----------|--------|
| F-02 | 🔄 更新 Skill | 上传新版 ZIP 替换文件 + 编辑基本信息，保留版本历史 | P0 |
| F-03 | 📥 下载 Skill | 将已入库 Skill 打包 ZIP 下载到本地 | P1 |
| F-04 | 🗑️ 删除 Skill | 单个 Skill 安全删除，含二次确认和关联数据清理 | P1 |
| F-05 | 📝 上传提示 | 上传区域显示填写要求和样例下载 | P1 |
| F-06 | 🔘 详情页操作 | 详情页顶部显示操作按钮（更新/下发/删除/下载） | P1 |

## 四、F-02 更新 Skill

### 4.1 可更新内容

注意，这里的新增、更新的交互都做一次更新。 
当有文件/文件夹已上传时，上传文件的框的文字，从【点击或拖拽文件上传】改为【请先删除已上传的文件】，下方已上传的文件删除时后恢复。

| 字段 | 是否可编辑 | 说明 |
|------|-----------|------|
| 文件（ZIP） | ✅ 可选 | 会回显之前的文件，和新增类似； 也是一样可以点击删除。 |
| slug（唯一标识） | ❌ 只读 | 入库后不可更改,作为唯一标识 |
| name (显示名称) | ✅ | 可自由修改（相比上传，默认不做覆盖） |
| description（描述） | ✅ | 可自由修改（相比上传，默认不做覆盖） |
| version（版本号） | ✅ 必填 | 系统校验格式（输入框里会有个灰色提示：新版本号需高于上一版本号x.y.z。），会有校验，如果格式不是x.y.z会报错，如果版本号比最新的版本号要低，会报错【新版本号需高于上个版本号x.y.z】 |
| changeLog（更新说明） | ⚠️ 选填 | 版本更新描述,下方提示，请填写本次更新内容，可【一键生成】； 默认不回显上次输入，有个【一键生成】按钮。 会说明本次修改的内容，一般是名称描述和文件，slug不能改，版本号没必要说明，分类也没必要记录。； 1、修改名称字段；2、修改描述字段；3、更新SKILL文件。  注意，有换行。例如1、修改名称字段；   2、更新SKILL文件；  注意：第一版即上传时的更新说明，默认为【首次上传】 |
| categories | ✅ | 多选分类（复用现有逻辑） |


注意：参考实现——clawhub目前也不支持在同个版本里只更新名称。

### 4.2 操作入口

| 位置 | 方式 |
|------|------|
| 列表页表格操作列 | 更新按钮； 现有的页面支持编辑Skill的分类，但把hover后的文案修改下，原来是【仅修改Skil的分类，近期会上线更新功能，届时可更换文件或修改Skill名称等信息。】改为【编辑分类】 |
| 详情页概览 Tab | 顶部操作栏「更新」按钮 |

### 4.3 更新对话框 (SkillUpdateDialog)

| 区域 | 内容 |
|------|------|
| 文件替换 | 可选区域：基本就是目前的（复用 SkillUploadDialog 解析逻辑），默认会回显上一个版本的文件，效果和上传技能时已上传文件一样的格式。文件替换会置灰，可以删除文件自己重新上传。 |
| 基本信息 | Slug（只读灰底）+ Name + Description |
| 版本信息 | Version（必填）+ ChangeLog（选填,自动生成模板） |
| 分类选择 | 多选标签 |
| 更新说明 | 如前述 |
| 操作 | 「取消」+「保存更新」（品牌渐变主按钮） |

**Dialog 尺寸**：`sm:max-w-lg` + `max-h-[90vh] overflow-y-auto`
文件至少要有一个，如果没上传要报错。 注意，默认【更新说明】


**版本号校验:**
- 格式必须符合 semver: `\d+\.\d+\.\d+`
- **必须高于当前版本号**（禁止降级）


### 4.6 版本历史展示

**位置：** 融合到详情页文件列表Tab左侧的版本选择栏。

**交互：** 版本条目右侧显示信息图标（i），或者鼠标停留在版本号超过1s，hover展示更新信息。

```
┌─ 版本选择 ────┐  ┌─ 文件列表 ──────────────┐
│                 │  │                          │
│ 1.2.0 最新    │  │ SKILL.md                 │
│ ✅2026-04-03 ℹ️ │  │ main.js                  │
│                │  │ config.json              │
│ 1.1.0          │  └──────────────────────────┘
│ ⚠️ 2026-04-01 ℹ️  │ [ hover ℹ️ 显示更新信息 ]
│               │
│ 1.0.0        │
│ ✅2026-03-28 ℹ️ │
│                 │
└───────────────┘
```

**版本条目 hover 展开详情：一个白色底的框**

```
┌──────────────────────┐
│ 更新说明: |
|xxx   默认新起一行如果有换行需换行 │
└──────────────────────┘
```

**说明：**
- ℹ️ 图标使用 lucide-react 的 `Info` 图标
- 更新信息包含：更新时间、变更说明（changeLog）

### 4.7 更新与下发的关系

- 文件更新后**不自动同步**已下发实例
- 下发记录表新增"待更新"筛选选项,用户可手动选择更新

## 六、F-04 删除 Skill

### 6.1 操作入口

| 位置 | 方式 |
|------|------|
| 列表页表格操作列 | 收入「更多」下拉菜单，|
| 详情页顶部 | 操作栏「删除」按钮 |

### 6.2 删除前置检查

| 检查项 | 条件 | 行为 |
|--------|------|------|
| 下发中 | 存在 `distributing` 状态记录 | ❌ **阻止删除**,置灰，hover："仅支持状态为正常的 Skill" |

### 6.3 确认对话框


**被技能包引用时的展示：**

```
┌─ 确认删除 ─────────────────────────────────┐
│                                              │
│  ⚠️ 警告                                     │
│                                              │
│  该 Skill 被以下技能包引用:                  │
│  • 全员通用技能包                            │
│  • 高级开发技能包                            │
│                                              │
│  删除后将自动从上述技能包中移除该技能。      │
│                                              │
│  [ 取消 ]          [ 确认删除 ] ← 红色      │
└──────────────────────────────────────────────┘
```

**无技能包引用时的展示：**

```
┌─ 确认删除 ─────────────────────────────────┐
│                                              │
│  确定要删除 Skill「{name}」吗？             │
│  此操作不可撤销。                            │
│                                              │
│  [ 取消 ]          [ 确认删除 ] ← 红色      │
└──────────────────────────────────────────────┘
```

### 6.4 删除后清理

| 关联数据 | 清理方式 |
|---------|---------|
| skills 缓存 | 从 `skillhub_enterprise_skills_cache` 中移除 |
| 技能包引用 | 从所有 `SkillInitialPackage.skills` 中自动移除 |
| 详情页状态 | 若正在查看该 Skill 详情,自动回退列表页 |

**技能包引用清理：**
- 删除 Skill 后,系统自动从技能包的 `skills` 数组中移除该 skillId
- 不影响已下发到租户的技能包实例（租户端继续使用已安装版本）

### 6.5 成功反馈

- `toast.success("Skill「{name}」已删除")`
- 列表自动刷新,移除对应项（带过渡动画）

## 十、交互流程总览



### 更新 Skill 流程
```
点击更新 → SkillUpdateDialog → 修改信息/上传新ZIP
  → [上传新文件] → 安全检测
  → 保存更新 → 追加版本记录
```

### 下载 Skill 流程
```
点击下载 → loading → JSZip 打包 → Blob → 浏览器下载
  → toast.success
```

### 删除 Skill 流程
```
点击删除 → 前置检查
  ├── 下发中 → 阻止
  └── 通过 → AlertDialog 确认
       → [被技能包引用] → 列出包名称 + 警告
       → 确认删除 → 清理关联数据
       → toast + 列表刷新
```

## 十二、常见问题澄清

### 12.1 安全检测对上传流程的影响

| 问题 | 答案 |
|------|------|
| 扫描失败时，前端是否需要重试按钮？ | ✅ 支持，在安全检测弹窗中提供「重新检测」按钮 |
| 扫描结果是否会影响后续的"更新"操作？ | ❌ 不影响，安全检测和更新是独立的流程 |
| 扫描中的 Skill 是否可以下发？ | ✅ 可以，安全检测不阻断下发流程 |

### 12.2 版本管理对下发逻辑的影响

| 问题 | 答案 |
|------|------|
| 已下发的旧版本如何处理？ | 不处理，租户继续使用已安装的版本 |
| "待更新"状态的判定逻辑是什么？ | 对比版本号，租户端版本与最新版本不一致即为"待更新" |
| 租户端版本一致性如何保证？ | 下发时携带 `meta.json` 文件，包含版本号信息，租户端据此判断 |

### 12.3 删除操作的影响范围

| 问题 | 答案 |
|------|------|
| 删除 Skill 是否影响已下发的租户实例？ | ❌ 不影响，租户端继续使用已安装的版本 |
| 删除后技能包如何处理？ | 自动从技能包的 `skills` 数组中移除该 skillId |
