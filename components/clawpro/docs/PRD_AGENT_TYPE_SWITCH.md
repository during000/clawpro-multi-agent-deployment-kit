## 一、用户端

### 需求点一：Agent 类型切换入口

#### 1. 入口位置

在“我的 Agent”详情页的实例类型信息旁提供 **切换** 入口，例如：

> 类型：OpenClaw　切换

入口使用轻量文字按钮，不在页面操作区增加新的主按钮。

#### 2. 场景区分

- **Agent 类型切换**：在当前实例上将 OpenClaw 切换为 Hermes，或将 Hermes 切换为 OpenClaw。
- **Agent 迁移**：保留原有跨实例迁入能力，用于在两个实例之间迁移 Agent 内容。

处理规则：

- 类型切换与 Agent 迁移使用独立入口和交互，不合并到同一个菜单。
- 类型切换不要求用户提前创建目标实例。
- 当前实例入口、实例 ID 和企业绑定关系保持不变，但无需在确认弹窗中重复展示。
- 仅受 ClawPro 管控且满足切换条件的 OpenClaw、Hermes 实例展示切换入口。
- 本地 Agent 或不支持切换的实例不展示切换入口。

#### 3. 验收标准

- 用户可以在实例类型信息旁找到“切换”入口。
- OpenClaw 实例可以发起切换至 Hermes。
- Hermes 实例可以发起切换至 OpenClaw。
- 原有“Agent 迁移”入口和跨实例迁入流程继续保留。
- 类型切换入口不会出现在不支持切换的实例中。

### 需求点二：切换确认

#### 1. 确认弹窗

用户点击“切换”后展示确认弹窗，标题根据目标类型变化：

- 当前类型为 OpenClaw：**切换为 Hermes？**
- 当前类型为 Hermes：**切换为 OpenClaw？**

弹窗说明：

> 切换期间实例暂不可用。配置、模型、技能、记忆和角色设定将自动迁移，会话历史将保留为只读记录。

#### 2. 展示规则

- 弹窗只用于确认，不展示多步骤流程、源类型与目标类型对比卡片或实例 ID。
- 不要求用户选择迁移内容，页面不展示不可操作的资源复选框。
- 不要求用户输入迁移口令、执行 ACLI 命令或手动传输迁移包。
- 用户点击“取消”后关闭弹窗，不发起切换。
- 用户点击“确认切换”后关闭弹窗并立即发起切换。

#### 3. 验收标准

- 弹窗标题能够正确展示目标 Agent 类型。
- 弹窗完整说明暂不可用范围、自动迁移内容和会话历史限制。
- 页面不会出现重复确认或冗余步骤。
- 点击“确认切换”后无需再次操作即可开始切换。

### 需求点三：切换中状态

#### 1. 页面状态

用户确认后：

- 确认弹窗立即关闭。
- 原“切换”入口原位更新为 **切换中**，并展示加载状态。
- “切换中”不可重复点击。
- 实例类型在任务完成前继续显示原类型。

#### 2. 处理规则

- 切换任务由 ClawPro 后台执行，用户无需停留在弹窗中等待。
- 页面根据任务状态接口恢复切换中状态，刷新页面后不应丢失任务进度。
- 同一实例存在进行中的类型切换任务时，不允许重复创建任务。
- 切换期间，涉及实例运行的操作应根据实际可用状态禁用或提示稍后再试。

#### 3. 验收标准

- 用户确认后弹窗关闭，“切换”入口立即变为“切换中”。
- 切换过程中不能重复发起任务。
- 页面刷新后能够继续展示真实任务状态。
- 页面不使用长流程弹窗、步骤条或模拟进度轮播表达后台状态。

### 需求点四：切换成功

#### 1. 页面反馈

切换成功后：

- 实例类型更新为目标类型。
- “切换中”恢复为可操作的“切换”。
- 页面以轻提示展示“已切换为 Hermes”或“已切换为 OpenClaw”。
- 不额外展示成功结果弹窗。

#### 2. 数据口径

页面按以下口径说明类型切换的资产处理范围：

- 配置、模型、技能、记忆和角色设定自动迁移为目标 Agent 可用格式。
- 会话历史保留为只读记录，不承诺在目标 Agent 中续接原会话。
- 当前实例入口、实例 ID 和企业绑定关系保持不变。

前端以平台返回的最终类型和任务结果为准，不根据本地计时自行确认真实切换成功。

#### 3. 验收标准

- 成功后实例类型正确更新为目标类型。
- 页面仅展示简洁成功提示，不出现冗余结果报告。
- 用户无需刷新页面即可看到最新实例类型。
- 刷新页面后实例类型与平台返回结果一致。

### 需求点五：切换失败与回滚

#### 1. 页面反馈

切换失败后：

- 实例类型继续展示原类型。
- “切换中”恢复为可操作的“切换”。
- 页面展示用户可理解的失败提示和重试建议。
- 不直接展示内部目录、完整命令、堆栈或原始系统错误。

#### 2. 处理规则

- 前端以平台返回的失败状态为准，不提前修改实例类型。
- 平台完成自动回滚后，页面恢复原类型及可用状态。
- 平台仍在回滚时，页面继续展示处理中状态，避免用户重复操作。
- 需要管理员定位时可提供错误追踪信息，但不在普通成功流程中展示任务 ID。

#### 3. 验收标准

- 切换失败不会误显示为目标类型。
- 自动回滚期间不能重复发起切换。
- 回滚完成后用户可以重新发起切换。
- 用户不会看到 API Key、迁移口令或内部系统错误详情。

## 二、页面状态与 Demo 说明

### 1. 页面状态

前端至少覆盖以下状态：

- OpenClaw 可切换至 Hermes。
- Hermes 可切换至 OpenClaw。
- 切换确认。
- 切换中。
- 切换成功。
- 切换失败并回滚。
- 实例不满足切换条件。

### 2. Demo 交互

- 点击实例类型旁的“切换”打开确认弹窗。
- 点击“确认切换”后关闭弹窗，入口变为“切换中”。
- Demo 任务结束后更新实例类型并展示轻提示。
- “Agent 迁移”继续打开原有跨实例迁入流程。

## 三、非本次需求范围

本次需求只设计 ClawPro 用户端前端页面，不包含：

- 类型切换后台任务编排和接口实现。
- OpenClaw、Hermes 运行时安装或卸载实现。
- ACLI 导入、导出和资产转换命令实现。
- 模型 Provider 字段映射和密钥恢复实现。
- 会话历史转换协议和逐资产保真度报告。
- 类型切换任务中心或历史记录页面。

## 四、待确认事项

- 当前实例类型切换的预计耗时和超时口径。
- 支持切换的 OpenClaw、Hermes 版本范围及兼容矩阵。
- 模型密钥和登录凭证是否默认自动迁移，以及失败时的用户提示口径。
- 会话历史只读保留是否为两个切换方向的统一限制。
- 切换失败后的自动回滚完成状态和错误信息字段。
