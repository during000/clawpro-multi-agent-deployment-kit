# ClawPro 工作流产品化方案 PRD

> 面向研发同学的产品需求文档
> 版本：v1.0｜日期：2026-08-06

## 一、文档概述

### 1.1 背景

ClawPro 已有项目资产管理能力（6 类资产在管控端管理），但项目是团队共同维护的——员工端没有入口，与实际工作流程错配。同时，团队协作缺少"工作流"这一载体，Agent 之间无法按 SOP 串联协作，重复性工作仍需人手动发起。

本次在**用户端（员工端）**建设项目协作中心，补齐资产管理入口，并新增工作流、任务看板、自动化等能力，形成「项目配置 → Agent 接入 → 资产下发 → 工作流定义 → 任务执行 → 自动化触发」的完整闭环。

### 1.2 核心目标

**让 Agent 成为项目执行的主体，人只管理/查看/派发，不录入内容。**

### 1.3 读者

研发同学（前端 + 后端），用于理解产品设计意图和每个功能点的交互逻辑，作为开发依据。

## 二、产品架构总览

### 2.1 整体页面结构

左侧项目列表 + 右侧工作台面板。选中一个项目后，工作台展示 4 个 Tab：

| Tab | 说明 |
|------|------|
| **总览** | 项目描述/目标、快速统计、资产数量、使用情况 |
| **资产** | 6 类资产管理（已有能力，本次优化展示） |
| **任务看板** | 任务全流程追踪 + 自动化配置入口 |
| **工作流** | 工作流的创建/编辑/管理 |

### 2.2 功能模块清单

| 模块 | 定位 |
|------|------|
| 总览页面 | 项目全貌一屏可见 |
| 资产管理 | 6 类资产增删、版本管理、同步模式（已有） |
| 任务看板 | 任务的可视化追踪与执行控制 |
| 工作流管理 | 可视化画布编辑器 + JSON 导入，定义 SOP |
| 自动化 | 定时器 + 工作流，到点自动创建任务 |
| 项目上手 Skill | 系统自动生成、随资产下发，Agent 接入即知晓项目全貌 |

## 三、功能模块详细需求

### 3.1 总览页面

#### 3.1.1 页面布局

总览页面从上到下分为四个区域：

**区域一：项目描述 + 项目目标**

- 两列卡片并排展示，分别展示「项目描述」和「项目目标」
- 文案超过 3 行自动截断，显示「查看全部」链接
- 点击「查看全部」弹窗展示全文

**区域二：快速统计（4 个卡片）**

| 卡片 | 展示内容 | 交互 |
|------|----------|------|
| 任务 | 总数 · 已完成 · 进行中 | 点击跳转到任务看板 Tab |
| 工作流 | 工作流总数 | 点击跳转到工作流 Tab |
| 成员 | 项目成员数 | — |
| Agent | 已接入 Agent 数 | — |

**区域三：资产数量统计**

- 按 6 大类资产分类统计数量，2 列网格布局
- 头部有「管理资产 →」链接，点击跳转到资产 Tab

**区域四：使用情况**

- 按资产大类切换（Tab 按钮切换分类）
- 条形图展示该分类下各条目的调用次数，按降序排列，最多展示 8 条

#### 3.1.2 数据来源

- 统计数据全部从项目对象实时派生（任务数、工作流数、成员数、Agent 数、资产数）
- 使用情况数据为调用次数统计，按资产分类展示

### 3.2 任务看板

#### 3.2.1 看板布局

4 列看板：

| 列 | 标签 | 包含的任务状态 | 圆点颜色 |
|------|------|----------------|----------|
| 待启动 | todo | todo | 灰色 |
| 进行中 | in_progress | in_progress、review | 蓝色 |
| 已完成 | done | done | 绿色 |
| 挂起 | hold | hold | 橙色 |

看板顶部有搜索框，支持按任务名称、工作流名称搜索。

#### 3.2.2 任务卡片信息

每张任务卡片展示：

| 信息 | 说明 |
|------|------|
| 任务标题 | 最多 2 行截断 |
| 删除按钮 | 右上角，点击删除任务 |
| 优先级标签 | 高（红）/ 中（橙）/ 低（灰） |
| 截止日期 | MM-DD 格式 |
| 节点进度条 | 「已确认节点数 / 总节点数」+ 百分比进度条（蓝色填充） |
| 来源标识 | 手动派发 / 批量导入 / Agent 上报 |
| 触发来源 | 外部触发（绿色）/ 周期任务（蓝色）/ 系统创建（仅非手动时显示） |
| 业务标签 | 需求/缺陷/汇报/评审等自定义 tag |
| 最新摘要 | 最近一个已确认节点的结果，2 行截断 |

点击任务卡片进入任务详情页。

#### 3.2.3 新建任务

点击看板「新建任务」按钮，弹窗表单：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 任务名称 | 输入框 | 是 | 最多 60 字符 |
| 工作流 | 下拉选择 | 是 | 从项目已有工作流中选择，显示名称 + 节点数；含「新建工作流...」选项可跳转工作流 Tab |
| 优先级 | 下拉选择 | 是 | 高/中/低，默认中 |
| 截止日期 | 日期选择 | 是 | — |
| 执行提示词（Prompt） | 多行文本 | 否 | 作为输入下发给工作流的第一个节点 |

创建后任务状态为 `todo`，出现在「待启动」列。

#### 3.2.4 任务状态流转

**任务级别状态机：**

```
todo → in_progress → done
                ↘ hold
```

- 任务详情页可通过状态下拉随时切换状态
- 全部工作流节点确认后，任务自动变为 `done`

**工作流节点级别状态机（核心）：**

| 状态 | 说明 |
|------|------|
| pending | 待执行，等待上游依赖完成 |
| running | 执行中 |
| stopped | 手动停止，保留上下文可重试 |
| confirmed | 已完成确认 |

流转规则：
1. **启动任务**：所有无上游依赖的起始节点变为 `running`
2. **节点执行完成**：自动变为 `confirmed`（不需要人确认）
3. **下游自动触发**：节点的所有上游依赖全部 `confirmed` 后，该节点自动变为 `running`
4. **手动停止**：`running` 可手动停止为 `stopped`，保留上下文
5. **重新执行**：`stopped` 可重新执行变回 `running`
6. **全部完成**：所有节点 `confirmed` → 任务自动 `done`

#### 3.2.5 任务详情页

任务详情页有三个子 Tab：

**子 Tab 一：工作流**

- 顶部栏：返回看板按钮、任务标题、来源工作流标签、状态下拉、启动按钮（todo 状态时）/ 固化为模板按钮（done 状态时）
- DAG 可视化：SVG 连线 + 节点卡片，按拓扑分层排列
- 每个节点卡片显示：节点标题、执行 Agent 下拉（可选择项目内已接入的 agent）、状态标签、运行信息（平台 + 本地/云端）
- 节点操作按钮（按状态显示）：
  - `running` → 显示「停止」按钮
  - `stopped` → 显示「重新执行」按钮
  - `confirmed` → 显示节点结果摘要
- 节点点击展开：查看该节点的 Prompt、输入数据、输出结果

**子 Tab 二：产物**

- 展示所有已确认节点的产物列表
- 产物格式支持 Markdown / JSON
- 可查看、复制产物内容

**子 Tab 三：信息**

- 展示任务元信息：创建时间、创建人、来源、关联工作流、优先级、截止日期

#### 3.2.6 固化为模板

任务状态为 `done` 时，详情页顶部显示「固化为模板」按钮：
- 点击后将当前任务的执行参数固化成一条新的工作流模板
- 用于把一次成功执行的经验沉淀为可复用 SOP

### 3.3 工作流管理

#### 3.3.1 工作流列表

工作流 Tab 展示当前项目下的所有工作流列表：
- 顶部有搜索框，按工作流名称搜索
- 每条工作流显示：名称、节点数、创建时间
- 操作：编辑、删除
- 「新建工作流」按钮

#### 3.3.2 画布编辑器

新建/编辑工作流进入画布编辑器，**从上往下纵向布局**。

**画布交互：**

| 操作 | 说明 |
|------|------|
| 鼠标拖动 | 平移画布 |
| 双击空白 | 创建新节点 |
| 悬停节点 | 显示「+」按钮，点击添加下游子节点 |
| 点击节点 | 选中并展开右侧编辑面板 |
| 节点间连线 | 自动根据依赖关系绘制 SVG 连线 |

**节点编辑面板字段：**

| 字段 | 说明 |
|------|------|
| 节点名称 | 必填 |
| Prompt 模板 | 该节点下发给 Agent 的执行指令 |
| 派发给 | 下拉选择，从项目已接入的 Agent 中选择执行者 |
| 上游节点 | 指定该节点依赖哪些前置节点（可多选） |
| 数据流 | 自动展示，无需手动配置：上游节点的输出作为本节点的输入 |

**节点间的数据流规则：**
- 前一个节点的结构化输出，自动作为下游节点的输入
- 一个节点可以有多个上游，所有上游全部确认后该节点才启动
- 数据流关系由上下游依赖自动推导，无需手动配置

#### 3.3.3 JSON 导入

除画布可视化编辑外，支持通过粘贴 JSON 快速导入工作流。

**JSON 格式：**

```json
{
  "name": "工作流名称",
  "description": "工作流描述（可选）",
  "nodes": [
    {
      "title": "节点标题",
      "promptTemplate": "该节点的 Prompt 模板",
      "dependsOn": ["上游节点标题"],
      "agentName": "执行 Agent 名称（可选）",
      "agentRole": "Agent 角色（可选）"
    }
  ]
}
```

**导入规则：**
- `dependsOn` 用节点标题引用上游节点，导入时自动解析为内部 ID
- 导入后可在画布继续编辑
- JSON 格式校验不通过时，提示错误信息

#### 3.3.4 工作流产生方式（三种）

| 方式 | 说明 |
|------|------|
| 人画 | 在画布编辑器手动创建和编辑 |
| Agent 经 MCP 回传 | Agent 在执行过程中，通过 MCP 接口回传工作流定义（含安全校验） |
| 历史沉淀成模板 | 任务执行完成后「固化为模板」，沉淀为可复用工作流 |

### 3.4 自动化

#### 3.4.1 入口

自动化融入任务看板页面（不单独设 Tab），点击任务看板页的「自动化」按钮，弹窗管理。

#### 3.4.2 自动化列表

弹窗展示当前项目下所有自动化配置：
- 每条显示：名称、关联工作流、调度类型、状态（启用/暂停）
- 操作：编辑、删除、暂停/启用、立即运行

#### 3.4.3 新建自动化

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 名称 | 输入框 | 是 | 自动化任务名称 |
| 关联工作流 | 下拉选择 | 是 | 从项目已有工作流中选择 |
| 调度类型 | 单选 | 是 | 周期 / 间隔 / 单次（见下表） |
| 调度参数 | 根据类型动态展示 | 是 | 见下表 |

**调度类型说明：**

| 类型 | 参数 | 说明 |
|------|------|------|
| 周期 | 星期几 + 时间点 | 如：每周一 09:00 触发 |
| 间隔 | 间隔小时数 | 如：每 6 小时触发一次 |
| 单次 | 指定日期时间 | 到指定时间触发一次 |

#### 3.4.4 自动化执行逻辑

1. 自动化启用后，到点自动创建一条任务（走关联的工作流）
2. 任务自动进入看板「待启动」列，工作流自动开始执行
3. 任务触发来源标记为「周期任务」
4. 支持随时暂停（暂停后不再触发）/ 启用 / 立即运行（立即创建一条任务）/ 编辑 / 删除

#### 3.4.5 设计原则

**自动化与 Agent 解耦**：自动化只绑定工作流，不绑定具体 Agent。执行者由工作流节点的派发配置决定。这样一个自动化可以驱动包含多个 Agent 节点的复杂工作流。

### 3.5 项目上手 Skill

#### 3.5.1 定位

系统内置的、自动生成的 Skill，随资产下发给 Agent。目的是让 Agent 接入项目后**无需打开页面即可获得项目全貌**，直接开始工作。

#### 3.5.2 自动生成内容

项目上手 Skill 由项目数据实时派生为 Markdown，包含以下信息：

| 信息 | 说明 |
|------|------|
| 项目名称 | — |
| 项目描述 | — |
| 项目目标 | — |
| 项目成员 | 成员列表 |
| 已接入 Agent | Agent 列表 |
| 工作流列表 | 当前项目所有工作流的名称和节点概览 |
| 任务列表 | 当前任务概况 |
| 工作流规则与 JSON 格式说明 | 告诉 Agent 如何通过 MCP 回传工作流（JSON 格式规范） |

#### 3.5.3 自动更新机制

项目上手 Skill 由 **ClawPro 后台自动根据项目情况生成和更新**，无需人工维护：

- Agent 关联项目后，后台自动生成项目上手 Skill 并随资产下发给 Agent
- 项目信息变更（名称/描述/目标/成员/Agent/工作流/任务等）后，后台自动重新生成 Skill 内容，随资产版本同步更新给所有已关联项目的 Agent
- 整个过程对用户透明，用户无需手动编辑或触发更新

### 3.7 项目管理（创建 / 编辑 / 删除）

项目列表位于页面左侧，展示当前用户归属的所有项目。每条项目卡片显示项目名称、成员数、资产编辑权限标识（铅笔=允许成员编辑，锁=只读）。点击项目卡片切换右侧工作台。

#### 3.7.1 创建项目

项目列表顶部有「新建项目」按钮，点击弹窗表单：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 项目名称 | 输入框 | 是 | 最多 40 字符 |
| 项目描述 | 多行文本 | 否 | 项目背景说明 |
| 项目目标 | 多行文本 | 否 | 项目目标描述 |

创建后项目出现在列表中，自动选中。

#### 3.7.2 编辑项目

每个项目卡片右侧有「⋯」三点菜单（鼠标悬停时显示），菜单包含「编辑项目」和「删除项目」。

点击「编辑项目」打开编辑弹窗，可修改以下内容：

| 字段 | 类型 | 说明 |
|------|------|------|
| 项目名称 | 输入框 | 最多 40 字符 |
| 项目描述 | 多行文本 | 项目背景说明 |
| 项目目标 | 多行文本 | 项目目标描述 |
| 允许成员编辑资产 | 开关 | 开启后项目成员可增删本项目资产，关闭则为只读 |

保存后项目信息即时更新，项目上手 Skill 同步刷新。

#### 3.7.3 删除项目

三点菜单中点击「删除项目」，二次确认后删除。删除项目会同时移除项目下所有成员关联、资产、工作流、任务等数据。

## 四、关键设计决策

| # | 决策 | 原因 |
|---|------|------|
| 1 | 任务说明改为执行提示词 | 任务说明不再是给人看的备注，而是下发给 Agent 的 Prompt |
| 2 | 自动化与 Agent 解耦 | 自动化只绑工作流，执行者由工作流节点决定，一个自动化可驱动多 Agent 协作 |
| 3 | 画布纵向布局 | 从上往下更符合阅读习惯 |
| 4 | 资产自动同步 | 关联到项目的 Agent 自动同步资产，无需手动下发 |
| 5 | 建设位置在员工端 | 项目是团队共维的，员工端补齐入口与实际工作流程匹配 |

## 五、验收标准

| 模块 | 验收点 |
|------|--------|
| 总览 | 项目描述/目标展示+全文弹窗；4 个统计卡数据准确、可跳转；资产数量分类统计；使用情况条形图按分类切换 |
| 任务看板 | 4 列看板正确分流；任务卡片信息完整；新建任务表单字段完整、工作流必选；任务状态流转正确（todo→in_progress→done）；节点自动确认+下游自动触发 |

| 工作流 | 画布编辑器：拖动平移、双击创建、悬停加子节点、节点编辑面板字段完整；JSON 导入格式校验+dependsOn 标题引用解析；导入后可继续编辑 |
| 自动化 | 弹窗管理；新建表单字段完整；三种调度类型正确；到点自动创建任务+走工作流；支持暂停/启用/立即运行/编辑/删除 |
| 项目上手 Skill | Agent 关联项目后自动获得；内容包含项目全貌 + 工作流 JSON 格式说明；项目信息变更后同步更新 |
| 资产管理 | 6 类资产增删+版本管理；关联 Agent 自动同步；副标题说明文案到位 |
