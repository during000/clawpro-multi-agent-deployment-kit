# ClawPro 工作流产品化方案说明

## 一、本次做什么

在已有的**资产管理**基础上，本次新增/重构了项目协作中心的五大能力，形成一个从「项目配置 → Agent 接入 → 资产下发 → 工作流定义 → 任务执行 → 自动化触发」的完整闭环。

> **建设位置说明**：本次能力建设全部在**用户端（员工端）**完成。此前项目资产管理入口只在管控端，但项目是团队共同维护的——员工端没有入口，与实际工作流程错配。本次补齐这一缺口，让团队成员在员工端即可管理资产、定义工作流、执行任务。

### 已有能力（保留并优化）

| 能力 | 说明 |
|------|------|
| **资产管理** | 6 类资产（模型配置/公共技能/企业技能/企业插件/企业MCP/企业规范）的增删、版本管理、同步模式。本次优化了展示方式和说明文案。 |

### 本次新增能力

| 能力 | 说明 |
|------|------|
| **项目管理** | 项目列表展示、创建项目（名称/描述/目标）、编辑项目（含「允许成员编辑资产」开关）、删除项目（二次确认） |
| **总览页面** | 项目描述/目标展示（长文案截断+弹窗查看全文）、资产数量分类统计、使用情况按资产类型切换展示（调用次数 Top 条形图）、快速统计（任务/工作流/成员/Agent 数量） |
| **任务看板** | 4 列看板（待启动/进行中/已完成/挂起），支持搜索（任务名称/工作流），新建任务时工作流必选、任务说明改为「执行提示词（Prompt）」下发给工作流第一个节点 |
| **工作流管理** | 可视化画布编辑器（从上往下纵向布局，支持鼠标拖动平移、双击空白创建节点、悬停快捷添加子节点），支持 JSON 导入（含 agent 指定），节点编辑面板含指定上下游、Prompt、数据流自动展示 |
| **自动化** | 融入任务看板页面（不再单独 Tab），点击「自动化」按钮弹窗管理。自动化 = 定时器 + 关联工作流，到点自动创建任务走工作流执行。支持周期/间隔/单次三种调度 |
| **项目上手 Skill** | ClawPro 后台自动根据项目情况生成和更新、随资产下发。Agent 关联项目后自动获得项目全貌（名称/描述/目标/成员/Agent/工作流/任务/工作流规则与 JSON 格式说明），无需打开页面即可开展工作。项目信息变更后后台自动重新生成并同步 |

### 关键设计决策

1. **任务说明 → 执行提示词** — 任务说明不再是给人看的备注，而是下发给 Agent 的 Prompt
2. **自动化与 Agent 解耦** — 自动化只绑工作流，执行者由工作流节点决定
3. **画布纵向布局** — 从上往下更符合阅读习惯
4. **资产同步说明** — 每个 Tab 加副标题说明页面用途，资产页明确说明「关联到项目的 Agent 自动同步资产」

## 二、核心产品逻辑

整个方案围绕一条主线运转：**项目承载工作流，工作流串联 Agent，任务驱动执行，自动化让重复工作自己跑。**

1. **项目是容器**：创建项目、配置成员和 Agent、管理资产——项目把人、Agent、资产组织在一起。
2. **工作流是 SOP**：把"某类工作怎么做"画成工作流（画布编辑或 JSON 导入），每个节点定义 Prompt + 派发给哪个 Agent + 上下游依赖，前一个节点的输出自动作为下游输入。
3. **任务是执行实例**：创建任务时选一条工作流 + 填执行提示词，工作流自动从第一个节点开始跑，节点完成后自动确认并触发下游，全程在看板可追踪。
4. **自动化是引擎**：把工作流绑到定时器上，到点自动创建任务跑工作流——重复性工作（周报收集、定期巡检）无需人手动发起。
5. **项目上手 Skill 是纽带**：ClawPro 后台自动根据项目情况生成，Agent 接入即知晓项目全貌，项目信息变更后自动更新同步，人不用手动维护。

> 一句话：**人定义工作流和自动化规则，Agent 按规则执行，系统自动串联和追踪。**

## 三、为什么做这些

### 核心目标

**让 Agent 成为项目执行的主体，人只管理/查看/派发，不录入内容。**

当前痛点：
- 项目是大家共同维护的，但**员工端没有项目资产管理入口**，跟实际工作流程错配
- 项目成员各自干活，经验散落，SOP 靠口口相传
- Agent 接入项目后不知道项目是什么、做什么、怎么做
- 任务派发后无法追踪执行进度，不知道 Agent 做到哪了
- 重复性工作（日报、周报、定期巡检）需要人手动发起

### 本次实现的目标

| 目标 | 对应能力 |
|------|---------|
| **Agent 接入即知晓项目全貌** | 项目上手 Skill 自动生成、随资产下发，Agent 无需打开页面即可获得项目上下文 |
| **SOP 固化为可复用工作流** | 工作流画布编辑 + JSON 导入，把"某类工作怎么做"沉淀为标准流程，任务创建时选工作流即按 SOP 执行 |
| **重复工作自动化** | 自动化定时触发工作流，自动创建任务到看板，无需人手动发起 |
| **任务全流程可追踪** | 任务看板 + 工作流节点进度条 + 产物汇总，人只需看进度和结果 |
| **降低使用门槛** | 搜索替代复杂筛选、副标题说明页面用途、JSON 导入快速创建工作流、画布支持鼠标拖动和双击创建 |

### 业务价值

1. **效率提升**：重复性工作自动化，SOP 固化复用，减少沟通成本
2. **质量保障**：工作流定义标准流程，任务按 SOP 执行
3. **Agent 赋能**：项目上手 Skill 让 Agent 即接即用，资产自动同步无需手动下发
4. **可观测性**：使用情况按资产类型展示，任务进度实时可查

## 四、用户使用路径和姿势

从**研发**和**PM 项目管理进度跟踪**两个角度说明。

### 角度一：研发

研发同学提前配置好工作流，通过本地 PC 端 agent 触发任务，即可开启工作。

```
1. 提前配置工作流（一次性）
   在项目协作中心创建工作流，例如：
     - 单元测试工作流：节点 = 拉取代码 → 执行单测 → 回传结果
     - issue 任务处理工作流：节点 = 接收 issue → 分析定位 → 修复 → 自测 → 提 MR
   每个节点定义 Prompt + 派发给哪个 Agent + 上下游依赖

2. 日常触发任务
   研发在本地 PC 端通过 agent 触发任务：
     创建任务 → 选择工作流 + 填写执行提示词（Prompt）
     → 任务进入看板，工作流自动执行
     → 各节点 Agent 协作完成，结果回传看板

3. 查看结果
   看板查看任务进度和产物（单测报告 / MR 链接等），无需人工跟进
```

### 角度二：PM 项目管理进度跟踪

一切以工作流和任务为载体。PM 要统计项目进展，找多个 agent 收集统计——建设一条工作流，并通过"自动化"功能自动触发。

```
1. 建设进度收集工作流（一次性）
   PM 创建一条"项目进度收集"工作流：
     - 每个节点派发给对应项目的 Agent，Prompt = "回传本周进展、阻塞、风险"
     - 节点按项目拆分，最后汇总节点统一整理

2. 配置自动化绑定工作流
   点击「自动化」→ 新建自动化 → 关联上面这条工作流
     → 设置调度（如每周一 9:00 周期触发）
     → 启用

3. 自动执行与查看
   到点自动创建任务 → 工作流自动执行各 Agent 收集 → 结果汇总到看板
   PM 只需看任务产物即可掌握全部项目进展，无需逐个找人问
```

### 各角色使用姿势

| 角色 | 主要操作 |
|------|---------|
| **项目管理员** | 配置项目信息、接入 Agent、配置资产、创建工作流、设置自动化 |
| **研发** | 配置研发类工作流（单测/issue 处理），本地 agent 触发任务，查看产物 |
| **PM** | 建设进度收集工作流，配置自动化定时触发，查看汇总结果 |
| **Agent** | 接收项目上手 Skill 获得项目上下文、接收资产获得能力、执行工作流节点、回传产物 |
