| 项 | 内容 |
|---|---|
| 创建人 | petzhou |
| 创建时间 | 2026-05-15 |
| 涉及端 | 管控端、员工端 |

---

## 背景

当前镜像管理页职能模糊（既要管镜像、又要决定"用户能用什么 Agent"），公共镜像由腾讯云持续更新，但管理员无法感知到这些更新，更没办法把"该升级了"这件事告诉员工。本次需求做以下整改：

1. 把"镜像管理"从"管镜像"重构为"管 Agent 类型"，心智更清晰
2. 引入"镜像更新记录"和"推送更新"功能，让管理员能看到平台动态、并主动通知员工
3. 增加"是否允许员工自助升级"的策略开关，让企业自由控制升级权限
4. 在 Agent 列表里也提供推送入口，让管理员在高频页面就能完成推送动作
5. 员工端展示当前版本号，并接收管理员推送的升级建议

## 需求点 1：镜像管理页面重构

**页面入口**：管控端 → 镜像管理（路由不变，页面标题改为「Agent 类型」）

### 1.1 标题
- 标题：**Agent 类型**
- 副标题：通过启用镜像决定用户端可以使用的 Agent 类型，支持自定义 Agent 类型。

### 1.2 主表结构
表格按 Agent 类型组织，每个类型一行。列定义：

| 列 | 内容 |
|---|---|
| Agent 类型 | 类型名 +「首选」徽章（如有）+ 兼容内核标签（仅自定义类型） |
| Agent 版本 | 当前启用镜像的版本号 + 维护方（腾讯云维护 / 企业自维护） |
| 镜像 | 镜像类型徽章（公共/自定义）+ 镜像名 + 镜像 ID + 状态 |
| 应用范围 | 全部用户 / 按组织（沿用现有功能） |
| 操作 | 用户可见 Switch + 设首选 + 切换镜像；自定义类型多一个删除类型 |

### 1.3 类型分两种
- **系统预设类型**：OpenClaw / Hermes Agent / LightClaw ACE，固定存在不可删
- **自定义类型**：管理员手动添加，需要选择"兼容内核"
  - 兼容 OpenClaw / Hermes Agent / LightClaw ACE：管控功能与对应系统类型一致
  - 自定义内核（不兼容上述）：管控台部分功能不可用，添加时必须勾选"我已知晓且允许用户进入终端"

### 1.4 公共镜像保护
- 公共镜像不可删除、不可编辑（这两个动作 toast 提示并拦截）
- 自定义镜像可编辑/删除，但当前用户可见的镜像不可删除

### 1.5 同类型互斥
- 同一个 Agent 类型，最多一个镜像处于"用户可见"状态
- 切换启用镜像时，旧镜像自动取消用户可见
- 关闭"用户可见"时：如果该类型是用户端首选类型，需先切换首选类型，否则拦截

### 1.6 不做
- 删除原右侧栏中的"+ 自定义 Agent 类型"快捷按钮（顶部已有大按钮）

### 2.4 右侧栏内容（自上而下）

```
1. Agent 类型锚点导航（保留）
2. 镜像新版本提醒条（仅在有更新时显示）
3. 推送更新 按钮（蓝紫渐变实心，醒目）
4. 正在提醒员工升级 列表 + 撤回（仅在有正在推送时显示）
```

#### 2.3.1 镜像新版本提醒条
- **何时显示**：存在某 Agent 类型的"启用镜像版本 ≠ 实例版本"
- **样式**：琥珀色背景柔和提示条
- **内容**：列出有新版本的 Agent 类型 + 版本号，最多 3 条；超过 3 条提示"等 N 个 Agent 类型"

#### 2.3.2 正在提醒员工升级 列表
- **何时显示**：当前有任意"正在推送"的记录
- **每条**：Agent 类型名 + 版本号 + 推送日期 + 撤回按钮
- **撤回**：点撤回 → 该类型推送状态立即清掉、用户端徽章同步消失

#### 2.3.3 查看全部更新记录
- 点击打开弹窗（不是抽屉），与公共镜像版本更新记录弹窗形态一致

### 2.5 推送更新 弹窗

**入口**（4 处）：
1. 镜像管理页右侧栏「推送更新」按钮
2. 镜像更新记录弹窗中"推送此类型最新版本"按钮
3. Agent 列表铃铛浮窗中的「推送提醒」按钮
4. （以上入口共用同一个弹窗）

**字段**：
- Agent 类型 *（下拉选择）

**字段不允许选/不在弹窗里的**：
- 不能选版本（自动 = 当前启用镜像的版本）
- 不能选实例范围（默认 = 该类型下所有实例版本 < 启用版本的员工）
- 不能编辑文案（自动生成"管理员推荐升级到 vX.Y.Z"）

**下拉里每条 Agent 类型的展示**：
- 类型名 + 当前启用版本 + 状态描述（"X 个旧版本"或"全部已是最新版"或"未启用"）
- "全部已是最新版"和"未启用"的类型不可选（灰掉）

**确认推送后**：
- 写入"正在提醒员工升级"状态
- 同类型若已有推送，自动覆盖
- toast 提示"已向 X 类型的 N 个旧版本实例推送升级提醒"

### 2.6 镜像更新记录 弹窗

- **形态**：居中 Dialog 弹窗（不是右侧抽屉），与公共镜像版本更新记录弹窗保持一致的视觉风格
- **筛选**：顶部 Tab 切换 全部 / OpenClaw / Hermes Agent / LightClaw ACE
- **时间线**：
  - 圆点：首次上线（紫色）/ 已推送（蓝色）/ 普通更新（灰色）
  - 每条：Agent 类型名 + 版本号 + 首次上线徽章（如有）+ 日期 + 镜像名（imageId）
  - 描述文案：参考 2.2 两种类型的展示
- **操作**：
  - 已在推送中的版本：展示"正在提醒员工升级此版本"徽章 + 撤回按钮
  - 未推送、且是该类型最新一条：展示"推送此类型最新版本"快捷按钮（仅最新一条有，老版本没有）

### 2.7 撤回入口（汇总）
撤回操作支持以下 3 个入口：
1. 镜像管理页右侧栏"正在提醒员工升级"列表
2. 镜像更新记录弹窗中对应版本旁
3. Agent 列表铃铛浮窗中

撤回是静默操作（员工端徽章直接消失，不发"撤回通知"）。

### 2.8 推送状态规则

| 规则 | 说明 |
|---|---|
| 一类一条 | 同一个 Agent 类型最多有 1 条"正在推送" |
| 推送目标版本 | 等于推送瞬间的"启用镜像版本"，不能手选 |
| 自动失效条件 | ① 管理员主动撤回 ② 管理员切换该类型启用版本 ③ 关闭该类型的"用户可见" |
| 不设过期时间 | 没有自动 N 天后过期的逻辑 |

## 需求点 3：平台策略增加自助升级开关

**位置**：管控端 → 平台策略 → 功能权限开关 板块下，紧跟"允许用户进入 Agent 终端"那一行

**新增开关**：
- 标题：**允许员工自助升级 Agent 版本**
- 描述：开启后，员工可在 Agent 详细配置中点击「一键升级」自助升级到管理员设置的版本。关闭后，「一键升级」按钮将隐藏，所有升级动作只能由管理员推送或批量发起（已通过推送提醒发出的升级仍可由员工点击徽章触发）。
- 默认值：**ON**（保持兼容存量企业）

**关闭后的影响**：
- 员工端 Agent 详情页的"一键升级"按钮隐藏
- 不影响"管理员推送"功能：用户端的"管理员推荐升级"徽章仍展示，员工点击仍可触发升级流程

## 需求点 4：Agent 列表通知 + 推送更新

### 4.1 铃铛 + 红点

**位置**：在原"批量更新"按钮**左侧**新增一个独立铃铛按钮

**显示规则**：
- 当存在某 Agent 类型的"启用镜像版本 ≠ 实例版本"时显示
- 没有版本不一致时整个铃铛不显示
- 与镜像管理页右侧栏的"镜像新版本提醒条"判断口径完全一致

**样式**：
- 铃铛图标，无背景色
- 右上角小红点
- hover 提示"X 个 Agent 类型有新版本，可推送提醒员工升级"

### 4.2 浮窗内容（点击铃铛打开）

**标题**：镜像有新版本

**副标题**：以下 Agent 类型的存量实例运行了旧版本，可推送提醒员工升级

**列表**（每个有版本不一致的 Agent 类型一行）：
- Agent 类型名 + 启用版本 + "新版本上线"徽章
- 子文字："有 X 个实例运行旧版本"
- 操作：仅「推送提醒」按钮
  - 点击 = 直接发起推送（与镜像管理页推送弹窗的效果一致，不跳出弹窗）
  - 已推送 → 改为展示"正在提醒员工升级此版本"徽章 + 撤回按钮

**底部说明**：
"推送提醒"是软通知，员工在用户端会看到升级建议，自行决定升级时机

### 4.3 不做
- 浮窗里**不放"批量升级"按钮**（避免和外部已有的"批量更新"按钮重复，让职责单一）

## 需求点 5：员工端版本展示 + 推送提醒徽章

**页面入口**：员工端 → 任意 Agent 实例的详情页

### 5.1 当前版本号展示

**位置**：实例头部第二行，紧跟实例 ID 后面（用 `·` 分隔）

**格式**：`v2026.4.21`（小字、中性灰）

### 5.2 管理员推荐升级 徽章

**位置**：当前版本号右侧

**显示规则**（同时满足）：
- 该 Agent 类型有正在推送的提醒
- 实例当前版本 < 推送版本

**样式**：
- 蓝色小徽章，喇叭图标 + 文字"管理员推荐升级 vX.Y.Z"
- hover 显示完整内容：
  - 推送文案（默认"管理员推荐升级到 vX.Y.Z"）
  - 推送人
  - 推送时间

### 5.3 徽章自动消失

以下任一条件满足，徽章立即消失（前端实时判断）：
- 实例当前版本已 ≥ 推送版本
- 管理员撤回了该类型的推送
- 管理员切换了启用版本（推送被自动失效）

### 5.4 与自助升级开关的联动

- 自助升级开关 ON：员工详情页"一键升级"按钮正常显示（既有产品行为）
- 自助升级开关 OFF：员工详情页"一键升级"按钮隐藏
- **管理员推荐升级徽章**始终展示（不受该开关控制），员工点击徽章仍可触发升级流程

## 跨需求点的统一约定

### "启用版本 ≠ 实例版本" 的判断口径
所有页面（镜像管理右侧栏 / Agent 列表铃铛）使用同一套判断逻辑：
- 取该 Agent 类型当前启用镜像的版本号
- 比对该类型下所有实例的版本号
- 只要存在 1 个实例版本低于启用版本，即视为"有版本不一致"

### 推送状态字段（业务语义）

每条推送包含以下信息：
- Agent 类型 ID
- Agent 类型展示名
- 推送的版本号
- 推送的镜像信息（名称 + 来源：公共/自定义）
- 推送时间
- 推送人
- 默认推送文案

### 推送状态在多端的同步要求
- 管控端推送/撤回 → 员工端徽章实时变化
- 员工端无操作（只读消费方）
