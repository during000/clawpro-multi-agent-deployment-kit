## 三、 根因追溯 (RCA) 与问题识别

> 说明：以下每一条都先写清 **PM 要解决的真问题（目的）**，再写 Skill 默认的错误手段。避免只罗列表面现象。

### 3.1 一条主线根因（贯穿所有反馈）
**受众错位 + 手段/目的倒置。** Skill 把"测试用例"默认理解成"给测试/开发执行的工程制品"，于是自然套用了编码索引、结构化表格、接口字段、渲染标签等工程化手段；但真正的受众是 PM，其目的是**"能直接读懂、快速判断、在任何阅读环境下都稳定可见"**。所有单点问题都是这条主线的分身。

### 3.2 逐条：真问题（目的） vs. 错误手段

| # | PM 要解决的真问题（目的，重点） | Skill 的错误手段（现象） |
|---|---|---|
| 1 | 靠自然阅读习惯就能定位内容、无需先学一套编码 | 默认输出 `[TP-1.1]`/`[F01]`/`[P0]`/ F·H·P·B·K·R 六系列编码交叉引用，强加认知负担 |
| 2 | 信息在任何环境下排版都稳定、不崩塌、方便扫读 | 默认用 Markdown 管道表格，列多内容长时排版崩塌、难读 |
| 3 | 每条用例的信息聚合成块、字段对齐、逐条清晰 | 信息平铺，字段不对齐，无分块，一眼看不出用例边界 |
| 4 | 不依赖外部背景知识、不跨区翻找就能读懂每条用例 | "关联规则"命名书面化、且把规则单独建表，逼用户上下翻看比对 |
| 5 | 只关注 PM 能验收的前端可见表现 | 预期结果混入 `agentInstanceId`、`initiatorType="admin"`、返回 JSON 等后端字段，偏离验收视角 |
| 6 | 前置说明只给读懂文档必需的最小信息 | 前置堆砌名词解释、诊断阶段说明，超出 PM 实际所需 |
| 7 | **对不同优先级做视觉分层，让人一眼区分层级、判断哪些必测** | 只是机械地"给优先级标个颜色"，未把"分层可辨"当成目标 |
| 8 | 分层标记在**纯 .md 源码环境下**直接可见 | 默认用 `<span style="color">` 依赖 HTML 渲染，纯 .md/GitHub/编辑模式下不可见 |

### 3.3 系统性缺陷根因（勾选）
- [x] **角色定位偏移（首要根因）**：思维停留在"给 QA/开发看的技术用例"，未立足"PM 只看前端表现、只做验收判断"的视角。第 1/2/4/5/6 条均由此派生。
- [x] **模板固化**：编码体系、管道表格写死在模板里，无法按受众（pm/qa）动态裁剪。
- [x] **交付载体假设错误**：默认交付物会经 HTML 渲染，用了依赖渲染器的 `<span style>`；PM 实际在 .md 源码环境阅读，视觉标记失效（第 8 条）。
- [x] **重点识别偏差（元根因，最重要）**：AI 反复把注意力落在"用什么编码/什么表格/什么颜色/什么标签"这些**手段**上，而没有先锁定"PM 要解决的真问题"这个**目的**。这是导致上述所有单点缺陷、以及本反馈文件早期版本本身写偏的共同元问题。

## 四、 转化为 Skill 优化策略（SOP）

> 排序规则：按对"PM 可用性"的影响从高到低。每项都遵循"先定目的，再给手段"。

### 【优化行动项 0 · 元原则，最高优先级】
在 SKILL.md 顶部确立**"目的优先"生成准则**：生成或优化任何内容前，先明确"目标受众是谁、他要解决什么真问题"，一切格式/编码/标记手段都必须服务于该目的，且**手段可替换、目的不可丢**。这是防止其余所有缺陷复发的总闸。

### 【优化行动项 1 · 受众定位，最高优先级】
增加受众参数 `audience: pm / qa`，并将 **PM 视角设为默认**。
- **目的**：让文档服务于 PM 的验收判断（只看前端可见表现）。
- **手段**：PM 模式强制——① 预期结果只描述前端可见现象，**严禁**出现接口字段、返回 JSON、技术变量名；② 去除所有工程化编码体系。

### 【优化行动项 2 · 可读性结构】
- **目的**：让 PM 靠自然阅读习惯即可定位、且信息在任何环境排版稳定、逐条边界清晰。
- **手段**：① 用自然层级标题（一、1、1）…）替代编码索引；② 默认排版由管道表格改为【序号】分块 + 双栏键值冒号对齐；横向对比（如多阶段状态）用多列并列双栏。

### 【优化行动项 3 · 自解释性】
- **目的**：PM 不依赖外部知识、不跨区翻找就能读懂每条用例。
- **手段**：① "关联规则"改为口语化的"业务规则"，规则内容**内联**在每条用例中，禁止单独建表让用户跨区比对；② 前置说明默认只保留"文档字段含义"一节，名词解释/阶段说明改为按需生成、不默认输出。

### 【优化行动项 4 · 优先级视觉分层】
- **目的（重点）**：对不同优先级（P0/P1/P2）做**视觉分层**，让 PM 扫一眼即可区分层级、快速判断哪些必测。这是要解决的真问题，任何实现都必须服务于"分层一目了然"。
- **实现约束**：交付物为纯 .md 时，分层手段必须在纯文本源码下即可见，不能依赖 HTML 渲染。
- **推荐手段（约束下的选择，可替换）**：emoji 色点（🔴 P0 / 🟠 P1 / 🟢 P2）置于用例标题行首；可叠加符号、缩进、分组标题增强层级感。
- **禁止手段**：`<span style="color">`、`<font color>` 等依赖 HTML 渲染的方案（纯 .md 环境不可见，无法达成分层目的）。
