# Skill 反馈记录 & 提炼分析

## 一、 基本信息
- **Skill 名称**：requirement-writer
- **应用场景**：管控端集成"龙虾医生" Agent 诊断与修复功能 PRD 生成
- **记录时间**：2026-07-15
- **用户反馈原文**：
  > 反馈 1："痛点和目标主要是：当前管理员巡检时，无法直接诊断和修复其他用户（普通员工）名下的异常 Agent……而且这个需求单生成'requirement-writer' skill 没有拉取到足够多的上下文，导致现在对需求的描述只有后半段，偏离原始主要需求"
  >
  > 反馈 2："面板内部展示占用说明，提示等待对方诊断完成后再操作——这是什么意思？除了'该 Agent 当前正在诊断中'之外还有其他的？"、"这里直接说明要提示的语句，不要用额外的多余的话描述"、"隐私隔离……这一点其实不属于规则，而是属于当前能力暂时达不到共享"、"这会有两种情况出现吗？什么场景下会出现第二种场景？"

## 二、 FEC 判定与归类（核心筛选！）

- [x] **【象限 A：系统性 Skill 逻辑缺陷】** (价值：⭐⭐⭐⭐⭐)
  *判定依据*：
  1. AI 在信息不充分时急于输出完整 PRD，导致遗漏核心需求主体（只覆盖后半段子功能）
  2. AI 凭空捏造了一个不存在的交互场景（"面板内被占用详情"——按钮置灰时面板打不开，该场景不可能发生）
  3. 文案描述过于冗余，不直接给出结论性提示语句，而是用多余的话绕弯子
  4. 将"当前能力限制"错误包装为"业务规则"

- [x] **【象限 B：隐性知识/规则漏洞】** (价值：⭐⭐⭐⭐⭐)
  *判定依据*：AI 对交互状态的逻辑推导存在漏洞——未理解"按钮置灰 → 面板不可打开 → 面板内不可能有占用提示"这一因果链条。

================================================================

## 三、 根因追溯 (RCA) 与问题识别
- **Skill 犯了什么错**：
  1. 第一次生成 PRD 时，仅基于对话后半段的子功能修改内容（跨端互斥、弹窗自适应）来组织文档，完全遗漏了核心主体功能（管控端集成龙虾医生诊断能力）
  2. 凭空编造了"面板内部被占用详情"这一交互场景及对应文案
  3. 用冗余描述包裹简单的提示语句，增加阅读理解成本
  4. 将技术能力限制（不支持对话共享）包装为设计规则（隐私隔离）

- **系统性缺陷根因**：
  - [x] **信息缺失未留白**：对话上下文中核心需求背景在早期轮次，Skill 未主动向上追溯完整上下文就开始生成，导致输出偏离。
  - [ ] **底座知识断层**
  - [x] **角色定位偏移**：没有站在"严谨审稿 PM"视角逐条验证每个场景是否真实可达，而是以"内容填充助理"心态凑条目。
  - [x] **模板固化**：模板驱动下倾向于"填满所有区块"，导致在没有真实场景支撑时编造内容来填充表格。

## 四、 转化为 Skill 优化策略（SOP）

- **【优化行动项 1】**：在 Skill 提示词中增加约束——"生成 PRD 前，必须先回溯整个对话历史确认核心痛点和目标，若上下文不足应主动询问，严禁仅基于最近几轮对话片段生成完整需求文档"
- **【优化行动项 2】**：在绝对禁止项中加入——"严禁凭空编造交互场景。每个场景/文案条目必须能通过逻辑推导确认其可达性（如：按钮置灰 → 面板不可打开 → 面板内场景不可达）"
- **【优化行动项 3】**：在输出风格约束中加入——"提示文案类描述必须直接给出最终提示语句，禁止用'展示明确提示，告知用户当前不可操作的原因'等间接描述替代具体文案"
- **【优化行动项 4】**：在知识表达约束中加入——"区分'设计规则'与'当前能力限制'。前者是主动选择，后者是暂时做不到。两者的表述方式应有明确区分，不可将能力限制包装为设计意图"
