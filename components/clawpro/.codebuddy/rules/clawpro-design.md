# ClawPro 设计规范守门（每轮 UI 改动必经）

> **本文件的定位**：只写「**何时触发 + 先判哪端 + 该去查哪个文件 + 交付前自检方向**」。
> **不写任何会变的具体值**（色值 / 圆角 px / 间距 / 字号 / token 名清单）——这些一改就过期，难维护。
> 需要任何具体值或组件细节，**一律按下方索引回权威源现查**，不要凭本文或记忆下结论。

---

## 强制开工协议（自动生效，无需用户提醒「按设计规范」）

> 目的：把守门从「默默执行」变成「可见动作」，让本规范每轮自动落地、且可被验证。

一旦识别到 UI 改动（见「何时触发」），在**动手改代码之前**，必须先在回复里输出一行判端声明，例如：

`【设计守门】端=admin｜已读权威源=SKILL.md + references/admin.md｜具体值将回 tokens/* 与 client/src/index.css 现查`

- **未输出该声明，不得直接改 UI**。
- 用户**无需**每次叮嘱「按设计规范」——识别到 UI 改动即自动触发本协议。
- 声明后再按下方流程执行；这一步也方便用户一眼检查本轮规范是否真的被执行。

---

## 何时触发

涉及 **颜色 / 圆角 / 间距 / 字号 / 按钮 / 卡片 / 表格 / 弹窗 / 图标 / 选中态 / hover 态** 的任何视觉改动，
哪怕只是「调个字号」「去个边框」「挪个间距」，都算 UI 改动，**必须过本守门**，别因改动小就跳过。

---

## 第 0 步：先判端（最重要 —— 判错端，后面全错）

先看**改的文件路径属于哪一端**，再去读该端权威源。**严禁拿一端规则套另一端**（各端在圆角 / variant / 卡片上规则不同，甚至相反）。

| 端 | 路径（任一命中） | 该端权威源（去读） |
|---|---|---|
| **管控端 admin** | `client/src/pages/admin/**` | skill 的 `SKILL.md` + `references/admin.md` |
| **用户端 tenant** | `client/src/pages/tenant/**`、`client/src/components/topnav/**` | `references/tenant.md` |
| **Landing / 营销** | `client/src/pages/landing/**` | `references/landing.md` |
| **跨端基础组件 ui** | `client/src/components/ui/**` | `component-specs/<组件>.md` + 组件源码 |

> Figma / 原型稿（`docs/*.html` 等）只作**结构 / 交互 / 文案**参考，其视觉值不可照搬，一律以本仓权威源为准。

---

## 通用流程铁律（方法论，不含具体值）

1. **不硬编码**：颜色 / 圆角 / 阴影 / 间距 / 字号一律走 token，禁字面值（`#hex` / `rgb()` / `text-gray-*` / 随意 px 圆角）。具体用哪个 token 按下方索引查。
2. **组件优先**：用现成语义组件（卡片 / 空态 / 危险确认 / 图标等），别用 `div` 现拼、也别照抄旧代码（旧代码可能不合规）。该端用哪个组件、组件怎么用，回权威源查。
3. **选中态 / hover 分组件核对**：不同组件的选中 / hover 规则不同（如导航树与列表 / 筛选项就不一样），改前回对应组件 spec 或源码确认，别套用别处。
4. **可交互元素三态一起过**：默认 / hover / 选中态一并改，不能只改单态；注意元素间距。
5. **拿不准就回权威源**：本文只指路，具体值与细节以权威源现查结果为准。

## 要查具体东西，去哪个文件（核心索引）

> 路径相对 `.codebuddy/skills/clawpro-portable-design-skill/`；运行时真值看仓库 `client/src/index.css`。

| 我要查… | 去这里 |
|---|---|
| **精确色值 / 品牌色** | `tokens/colors.md`；真值核对 `client/src/index.css` 的 `:root` |
| **圆角 / 阴影值** | `tokens/radius-shadow.md` |
| **间距值** | `tokens/spacing.md` |
| **字号 / 字重 / 行高** | `tokens/typography.md` |
| **全量 token（机器可读）** | `tokens/design-tokens.json` |
| **某端整体规范 / Workflow** | `SKILL.md`（admin）/ `references/tenant.md` / `references/landing.md` |
| **某组件视觉 + 用法** | `component-specs/<组件>.md`；无独立 spec 时以组件源码为准 |
| **反复踩过的坑（含具体 case）** | `docs/COMMON-ERRORS.md` |
| **token 实际定义（运行时真值）** | 仓库 `client/src/index.css` 及组件源码 |

> 🔒 不要写死任何行号——文件一改行号就失效，按**变量名 / 组件名**搜。

## 交付前自检（查方向，不列具体值）

- [ ] **端别对**：没把 A 端的圆角 / variant / 卡片组件套到 B 端。
- [ ] **无硬编码**：颜色 / 圆角 / 间距 / 字号都走 token，没有字面值。
- [ ] **组件对**：用了该端规范组件，不是 `div` 拼、不是照抄旧代码。
- [ ] **选中 / hover 对**：按对应组件标准核对过，没乱套别处的选中 / hover 规则。
- [ ] **三态齐全**：默认 / hover / 选中都改了，间距正确。
- [ ] **存疑项已回权威源核对**：凡拿不准的具体值 / 组件细节，都按上方索引查证过，而非凭记忆。

任一项存疑，回权威源查证、回改后再交付。
