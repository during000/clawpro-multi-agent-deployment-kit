# 反馈单生成模板（生成权威）

> 本文件是反馈单结构的**单一权威来源**。触发落盘时，AI 复制以下模板，在 `.codebuddy/feedback/{skill-name}/` 下生成 `{YYYY-MM-DD}-{scene-en-name}.md`。
> 连续多轮同一场景 → **追加**到同一文件（补原话/补 RCA/补行动项），不新建。

```markdown
# Skill 反馈记录 & 提炼分析

## 一、 基本信息
- **Skill 名称**：{当前使用的 Skill，如：requirement-writer}
- **应用场景**：{具体场景，如：管控端集成"龙虾医生" Agent 诊断功能 PRD 生成}
- **记录时间**：{YYYY-MM-DD}
- **用户反馈原文**：
  > "{PM 的原始修改意见或抱怨，原汁原味摘录，禁止粉饰}"

================================================================

## 二、 FEC 判定与归类（核心筛选！）
> 勾选本次反馈所属象限。

- [ ] **【象限 A：系统性 Skill 逻辑缺陷】** (价值：⭐⭐⭐⭐⭐)
  *判定依据*：格式冗余、废话铺垫过多、写了前端组件/API 等代码细节、或编造了无根据的 UI 尺寸。
- [ ] **【象限 B：隐性知识/规则漏洞】** (价值：⭐⭐⭐⭐⭐)
  *判定依据*：对业务模型（如跨所有者权限）、双端对称交互、或底座资源生命周期的理解存在严重漏洞。
- [ ] **【象限 C：纯业务内容微调】** (价值：⭐ - 仅作记录，无需改 Skill)
  *判定依据*：本次任务的业务决策临时微调（如"本期先不做对话修复了"）。
- [ ] **【象限 D：彻底的无价值噪声】** (价值：❌ - 请删除本文件)
  *判定依据*：拼写纠错、偶发输入错误、无实质建议的抱怨。

================================================================

## 三、 根因追溯 (RCA) 与问题识别
- **Skill 犯了什么错**：{AI 输出不佳的具体表现，如：凭空捏造了 40% 宽度和 20 分钟超时逻辑}
- **系统性缺陷根因**：
  - [ ] **信息缺失未留白**：输入未提及该参数，AI 开启了"自动填充数值"的默认幻觉。
  - [ ] **底座知识断层**：AI 不知道平台底座的真实生命周期/限制。
  - [ ] **角色定位偏移**：思维没立足于"资深 PM 跨所有者全局运维"视角，降级为普通助理。
  - [ ] **模板固化**：模板过于死板，无法按需求复杂度动态裁剪模块。

================================================================

## 四、 转化为 Skill 优化策略（SOP）
> 先锁定用户要解决的真问题/目的，再写手段；手段须符合交付物真实约束。

- **【优化行动项 1】**：{目的 + 手段。如：目的=严禁捏造前端 UI 细节参数；手段=无提及一律用 `⚠️待补充` 占位留白}
- **【优化行动项 2】**：{如：知识库补充"临时诊断 Agent 生命周期为 12 小时无对话自动销毁"}
```
