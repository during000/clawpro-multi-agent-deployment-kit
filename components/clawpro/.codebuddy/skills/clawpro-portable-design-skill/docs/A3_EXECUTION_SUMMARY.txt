  - Rule "emoji-icon" checks emoji, not inline SVG paths
  - Rule "old-brand-color" checks #007AFF but not #1447E6 (new hardcoding)
  - Rule "inline-box-shadow" checks JSX "boxShadow:" but not CSS "box-shadow:"
  - Rule "large-radius" checks className "rounded-xl" but not CSS variable "0.75rem"
  - No rules for: file duplicates, token value redundancy, component API constraints

Root Reason:
  - Script designed for JSX/TSX, doesn't cover CSS files comprehensively
  - Rules focus on "prevent old mistakes" not "prevent new code of same type"
  - No mechanism to check CSS-to-CSS consistency (value duplication)
  - No mechanism to validate component API contracts

Impact:
  - Violations slip through undetected
  - Heavy reliance on manual code review (doesn't scale)
  - No automated feedback to developers (slower iteration)

  - Self-Audit Checklist (§8) is MANUAL list, not enforced

  - No "continuous execution" mechanism (rules enforced only at PR review time)
  - Team process assumes human reviewers catch everything
  - New developers don't know what's expected until they violate it

Impact:
  - Even if rules are clear & scripts are complete, violations get committed
