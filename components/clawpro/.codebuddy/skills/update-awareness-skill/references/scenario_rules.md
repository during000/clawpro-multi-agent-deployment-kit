# 管控端版本更新场景规则

识别变更时，先判断层级，再判断具体场景。输出时保留场景编号，方便和设计、产品、研发对齐。

## 一、结构层：页面结构级别变化

### 1.1 新增子页面

产品新增完整子页面，用户此前从未见过这个页面。

判断信号：

- 新增路由、页面文件、侧边栏入口、导航入口或 Tab 页面
- 页面承载一组完整任务，而不是单个按钮或字段

感知要点：

- 用户不知道这个页面存在，也不会主动寻找。
- 需要告诉用户“有了新地方可以去”，以及“去那里能做什么”。

推荐组件：`导航提示条 + New Tag`

### 1.2 页面重新排布

同一页面内，功能区域的位置、顺序、分组发生变化。

判断信号：

- 页面从上下布局变为左右布局
- 列表、操作区、详情区、筛选区的位置发生明显变化
- 页面结构重组但功能本身未完全迁移到别处

感知要点：

- 用户回到页面时会发现“长得不一样了”。
- 用户可能找不到原来习惯的操作位置。
- 需要帮助用户建立新的空间映射。

推荐组件：`导航提示条 + 重要操作变更气泡引导`

### 1.3 功能位置变动

某个功能从 A 页面移动到 B 页面，或入口层级发生升降。

判断信号：

- 功能从独立 Tab 移入某个子页面
- 功能从设置页移动到主页
- 一级入口变成二级入口，或二级入口提升为一级入口

感知要点：

- 用户按旧习惯去原位置会找不到功能。
- 需要告诉用户“功能搬家了，新地址在哪里”。

推荐组件：`导航提示条 + 页面入口气泡引导`

### 1.4 页面整合或拆分

多个页面合并为一个，或一个页面拆分为多个。

#### 1.4.1 多个页面合并为一个

判断信号：

- 原来多个路由或页面合并到一个页面
- 通过 Tab、分组、筛选切换承载原页面能力

感知要点：

- 用户可能不知道整合后的页面包含原来多个页面的功能。
- 用户可能在旧路径找不到内容。

推荐组件：`导航提示条 + 页面入口气泡`

#### 1.4.2 一个页面拆分为多个

判断信号：

- 原页面的模块拆成多个独立页面、子页面或侧边栏入口
- 原入口继续存在但内容被分流

感知要点：

- 用户需要知道拆分后的页面分别承载什么任务。
- 用户需要从旧路径快速找到新位置。

推荐组件：`导航提示条 + 侧边栏说明详情 + 页面入口气泡引导`

### 1.5 页面入口新增或下线

侧边栏、导航栏、Tab 栏出现新入口，或原有入口被移除。

#### 1.5.1 页面入口下线

判断信号：

- 入口被删除、隐藏、禁用或标记即将下线
- 代码中出现 deprecated、disabled、offline、legacy 等语义

感知要点：

- 下线入口如果不告知，用户会以为功能丢失。
- 下线前应给预告期和替代路径。

推荐组件：

- 下线预告期：`导航提示条 + 要下线入口禁用一段时间 + 禁用入口说明气泡`
- 下线告知期：`导航提示条`

#### 1.5.2 页面入口新增

判断信号：

- 侧边栏、导航栏、Tab 栏新增入口项
- 新入口指向非临时功能

感知要点：

- 新增入口不提示时，用户可能长期不点击。

推荐组件：

- 非一级导航功能：`导航提示条 + New Tag`
- 一级导航功能：`导航栏对应功能旁展示气泡`

## 二、元素层：UI 元素级别变化

### 2.1 新增按钮或操作入口

页面中新增按钮、链接、下拉菜单项或其他可交互元素。

判断信号：

- 新增按钮、菜单项、链接、操作列、批量操作
- 新增“查看版本历史”“加入初始技能包”等动作

感知要点：

- 按钮虽然可见，但用户可能视而不见。
- 需要说明“多了一个可以点的东西”和“点击后会发生什么”。

推荐组件：

- 重要功能：`导航提示条 + 功能入口附近气泡`
- 次级功能：`用户进入对应界面时展示功能介绍气泡`

### 2.2 新增表格列或展示字段

列表或表格新增一列数据或展示字段。

判断信号：

- 新增表格列、状态列、信息字段、详情字段
- 新增“分发状态”“所属技能包”等信息

感知要点：

- 列的增减改变信息密度。
- 用户可能不知道新增字段含义，或根本没注意到。

推荐组件：

- 重要内容：`导航提示条 + 功能入口附近气泡`
- 次级内容：`用户进入对应界面时展示功能介绍气泡`

### 2.3 新增筛选、排序或分组选项

筛选栏、排序选项、分组方式中新增可选项。

判断信号：

- 新增筛选项、排序项、分组选项、视图切换
- 新增“按分发状态筛选”“按技能包分组”等维度

感知要点：

- 这类变化通常不会被主动发现。
- 但可能显著提升管理员操作效率。

推荐组件：

- 重要内容：`导航提示条 + 功能入口附近气泡`
- 次级内容：`用户进入对应界面时展示功能介绍气泡`

### 2.4 名称或文案变更

菜单名称、按钮文案、标签、提示文字、状态枚举等发生变化。

判断信号：

- “插件管理”改为“企业插件库”
- “发布”改为“分发”
- “进行中”改为“分发中”

感知要点：

- 用户可能困惑“这是不是原来那个东西”。
- 需要说明“只是改名，功能不变”或“名称变化且含义有调整”。

推荐组件：

- 只在用户进入对应页面并看到该元素时展示。
- 标题文案可在新名称右侧加 `(原 XXX 功能)`。
- 元素附近主动出现解释气泡，说明变更情况。

### 2.5 新功能 New Tag

某个元素出现“新”标识，表示最近新增的功能或入口。

判断信号：

- 侧边栏入口、Tab、按钮、功能区旁新增 New Tag

感知要点：

- New Tag 是最轻量的感知手段。
- 上线时间以对应 Campaign 的 `launched_on` 为准；必须明确 `duration` 或曝光次数，避免长期挂 New。

推荐策略：

- 默认展示 14 天。
- 入口类变更可展示到用户首次点击后移除。
- 最长不超过 30 天，除非产品明确要求。
- New Tag 仍需执行管理员知情判断，但跨端判断不限于 New Tag。每一项用户端变化都要判断管理员是否需要配置、治理、安全、数据访问、支持、解释或故障排查。用户端支持云端 Agent 对话等重要能力时，即使没有直接管控配置，也应生成管理员产品动态；纯下载、浏览、帮助或静态展示入口通常不需要。

### 2.6 细节优化叠加

多个微小体验优化叠加，包括文案调整、间距优化、交互微调、颜色、图标、圆角、阴影等视觉变化。

判断标准：

- 只做视觉展示优化或操作更流畅：`不展示`
- 改变用户操作路径或操作结果：需要感知
- 修复用户已知问题：值得感知
- 多项优化叠加导致页面认知明显变化：可汇总感知

推荐组件：

- 仅视觉优化或轻微流畅性优化：`不展示`
- 操作路径大幅调整：`导航提示条 + 常驻操作引导`
- 操作路径简单变化：`入口处气泡说明`
- 已知问题修复：`导航提示条 + 对应页面内 Alert`

## 三、逻辑层：不可见逻辑级别变化

### 3.1 底层逻辑变更

操作表现不变，但背后处理逻辑变化，导致行为结果可能不同。

判断信号：

- 分发逻辑、同步逻辑、分组逻辑、计算逻辑变化
- 例如从全量分发改为增量分发，从 1 用户 1 分组改为 1 用户多分组

感知要点：

- 用户可能以为还是旧逻辑。
- 如果结果和预期不一致，必须明确告知。

推荐组件：`导航提示条 + 对应页面内 Alert 解释变化详情`

### 3.2 规则或策略变更

业务规则、校验规则、策略发生变化。

判断信号：

- 命名规则、数量上限、重试策略、审批规则、校验规则变化
- 用户按旧规则操作会被拒绝或影响其他页面操作

感知要点：

- 规则变化直接影响用户能做什么、不能做什么。
- 重点业务规则必须提示；普通输入规则可在原组件下方更新说明。

推荐组件：

- 重点业务或策略变更：`导航提示条 + 对应页面 Alert`
- 普通输入规则变更：`对应组件下方规则说明`

### 3.3 计费或配额变更

与费用、用量上限、资源配额相关的规则变化。

判断信号：

- 免费租户数量上限调整
- 插件分发并发数限制变更
- 用量、额度、成本、套餐权益变化

感知要点：

- 直接影响成本和使用范围，管理员必须知晓。

推荐组件：

- 重点业务或策略变更：`导航提示条 + 对应页面 Alert`
- 普通输入规则变更：`对应组件下方规则说明`

## 四、系统层：账号和安全级别变化

### 4.1 账号体系变更

登录方式、认证逻辑、账号关联关系发生变化。

判断信号：

- 新增 SSO、OneID、统一身份平台
- 登录入口、认证流程、账号绑定关系变化

感知要点：

- 账号体系影响所有用户登录入口和认证流程。
- 这是最高等级变更；影响不确定时必须标注风险并请求确认。

推荐组件：`导航提示条 + 页面 Alert + 必要时强提醒弹窗`

### 4.2 权限体系变更

角色权限、功能权限、数据权限定义或范围变化。

判断信号：

- 新增角色
- 普通管理员权限被收窄
- 功能从所有管理员改为超级管理员可见

感知要点：

- 权限变更敏感，用户可能突然做不了原来的事，或多了新能力。

推荐组件：`导航提示条 + 页面 Alert + 权限影响说明`

### 4.3 数据合规或隐私政策变更

数据处理方式、隐私政策、数据留存策略变化。

判断信号：

- 数据留存期限调整
- 新增数据导出能力以满足合规要求
- 日志记录范围扩大

感知要点：

- 合规类变更通常需要明确知情，甚至需要确认同意。

推荐组件：`导航提示条 + 页面 Alert + 必要时确认弹窗`

## 五、跨端层：双端联动级别变化

### 5.1 C 端变化需告知管控端

C 端用户侧发生变化，管控端管理员需要知道，因为会影响管理、治理、支持、解释或风险判断。该判断是所有用户端变化都要执行的独立检查，不要求主场景先被分类为跨端层。

判断信号：

- C 端新增功能、行为、入口或配置结果
- C 端新增页面、导航入口、Tab 或功能入口，并且新增的是会影响管理员管理、配置、下发、更新、权限、状态解释或用户咨询口径的能力
- C 端新增 skill 下发更新、skill 管理、启停状态、分发结果、使用范围等管理员需要知晓的能力
- C 端新增云端 Agent 对话、模型调用、工具调用、外部连接、数据访问或内容生成等重要能力，管理员需要知道用户现在能做什么以及如何支持、治理或排查
- 管理员虽看不到 C 端页面，但需要理解用户侧变化

感知要点：

- 管理员需要知道 C 端变化对配置、管理、治理、支持和解释用户行为的影响。
- 如果 C 端只是多了一个下载 skill、浏览内容、查看帮助或静态展示的位置，不改变管理员管理对象和解释口径，则不生成管控端卡片。
- 管理员需要管理或知情时，应在管控端看到一张产品动态卡片，而不是只依赖 C 端页面里的 New Tag。

推荐识别项：`GuideAdminNotify 产品动态卡片 + ProductUpdatesDrawer 详情承接`。本 skill 只提醒用户先进行卡片文案生成与审核，不决策或开发该组件；若变化同时影响配置规则，再补可独立审核的 `导航提示条 + 对应配置页 Alert 或说明详情`。

### 5.2 管控端变化需告知 C 端

管控端某些变化会影响 C 端用户，需要让 C 端用户知道。

判断信号：

- 管控端新增配置，保存后 C 端立即生效
- 管理员配置会改变 C 端入口、能力或默认内容

感知要点：

- C 端用户需要知道“这是管理员为你配置的”。

推荐组件：`管控端导航提示条 + C 端对应页面提示占位`

## 场景优先级

当多个场景同时命中，保留所有产生独立认知问题的场景。以下顺序只用于确定展示优先级、排队和冲突避让，不用于删除低优先级提示：

1. `4.3 数据合规或隐私政策变更`
2. `4.1 账号体系变更`
3. `4.2 权限体系变更`
4. `3.3 计费或配额变更`
5. `3.2 规则或策略变更`
6. `3.1 底层逻辑变更`
7. `1.5 页面入口新增或下线`
8. `1.3 功能位置变动`
9. `1.4 页面整合或拆分`
10. `1.2 页面重新排布`
11. `1.1 新增子页面`
12. `5.1 / 5.2 跨端联动变化`
13. `2.1 / 2.2 / 2.3 元素新增`
14. `2.4 名称或文案变更`
15. `2.6 细节优化叠加`
