# 中文文案规范

更新提示文案要短、明确，并且必须先区分端类型。

- 管控端：可以更专业，允许使用管理员熟悉的业务概念、配置项、权限、分发、配额、规则等术语。
- 用户端：必须更易懂，优先写“你现在可以做什么”“功能在哪”“会带来什么变化”，避免后台术语、平台术语、策略术语。

## 字段结构

不要预设所有组件都有 `title`、`body`、`primary_cta` 和 `secondary_cta`。先按 `component_contract.md` 的“组件内容槽位”确定组件变体，再为真实存在的槽位生成文案。

- 标题槽位存在时：4-14 个中文字符，说明变化对象。
- 正文或说明槽位存在时：1-2 句短句，说明变化内容和用户价值。
- 操作槽位存在且用户需要下一步动作时：1-6 个字，准确描述动作。
- 组件不支持按钮或当前场景不需要动作时，省略按钮，不用“知道了”或“去看看”补齐结构。
- 组件自带的关闭、翻页、步骤导航文案按组件规则处理，不重复生成人工 CTA。

## GuideAdminNotify 专项规则

`GuideAdminNotify` 不是普通页面公告，它要遵守组件自身的卡片文案约束：

本节仅用于形成交给文案负责人的生成与审核 brief。`update-awareness` 不把示例改写成可开发终稿，也不据此决策或执行 `GuideAdminNotify` 开发。

- `title` 建议带端前缀，格式优先写 `用户端 | {功能名}` 或 `管控端 | {功能名}`。
- 单条卡片标题建议控制在 `≤16` 个中文字符；其中 `{功能名}` 应尽量短，只保留能力名，不要把影响说明塞进标题。
- `desc` 建议控制在 `≤30` 个中文字符，只写“新增了什么能力”和“管理员为什么要知道”，不要展开写实现细节；在 `Implementation Plan` 中对应卡片描述槽位。
- `btnText` 建议控制在 `≤6` 个中文字符；在 `Implementation Plan` 中对应卡片按钮槽位；单条默认优先 `立即体验` 或 `查看详情`。
- 如果会打开 `ProductUpdatesDrawer`，CTA 优先写 `查看详情`；如果会直接进入目标页面，CTA 可写 `立即体验`。
- 聚合卡片标题由组件自动生成 `管控端有 N 项新增` / `用户端有 N 项新增`，skill 不应手写别的聚合标题格式。
- 聚合卡片描述会自动把多条标题去掉端前缀后用 `、` 拼接，所以单条标题必须可独立阅读，避免写成长句。

普通 onboarding 组件使用共享软校验：标题 `≤14` 字、正文 `≤60` 字、CTA `≤6` 字。生成文案时应主动压缩，不要依赖组件截断。

不推荐写法：

- 标题写成完整说明句，例如 `用户端 | 新增 skill 下发更新和管理能力，管理员可查看影响范围`
- 描述里堆砌实现词，例如 `新增接口、组件、版本同步逻辑`
- CTA 写成长句，例如 `去产品动态查看具体更新内容`

## 语气

- 先说用户能理解的变化，不说实现细节。
- 避免 PR、重构、组件、接口、diff 等研发词。
- 避免夸张表达。
- 如果功能只是改名，要明确“原 XXX”。
- 如果规则或权限会影响操作结果，要明确提醒。
- 如果需要用户行动，直接写下一步。

## 端侧规则

### 管控端文案

- 允许使用“分发状态”“权限范围”“配额限制”“策略调整”“配置生效”等术语。
- 可以明确写出受影响角色、入口层级、规则变化和操作路径变化。
- 更强调效率、控制范围、规则影响和团队协作。

示例：

- `现在可以按分发状态筛选插件列表，更快定位待处理项。`
- `普通管理员已无法查看分发状态，请改由超级管理员处理。`

### 用户端文案

- 优先使用简单直白表达，避免“分发、租户、策略、规则校验、配额”这类后台术语，除非产品内本来就直接面向用户展示。
- 少写系统内部结构，多写用户结果。
- 优先使用“你现在可以”“可以在这里找到”“这个功能会影响”。

示例：

- `你现在可以按状态筛选内容，更快找到想看的项目。`
- `这个入口换了位置，现在可以在“我的工具”里找到。`

### 同一变化的双端写法示例

管控端：

- `初始技能包配置保存后会立即对用户端生效。`

用户端：

- `管理员为你开启的新技能包已经生效，现在可以直接使用。`

### 跨端产品动态卡片示例

供文案生成与审核参考的 `GuideAdminNotify` 单条写法：

- 标题：`用户端 | Skill 管理`
- 正文：`支持下发更新和状态管理，便于统一说明用户侧变化。`
- 按钮：`查看详情`

不适合 `GuideAdminNotify` 的写法：

- 标题：`用户端新增 Skill 下发更新和管理能力，管理员可在产品动态中查看影响范围`
- 正文：`本次更新新增了多个入口、列表、状态列和相关接口逻辑，请进入页面查看`

## 场景模板

下列“按钮”是动作语义建议，不代表每个组件都必须显示按钮。只有所选组件及内容变体支持操作槽位时才使用；例如 `GuideUpdateBar` 映射为待审核的详情入口 brief，且由独立流程完成终稿与开发；纯文本 `GuidePointBubble`、`GuideNewTag`、`GuideHighlightBubble` 和抽屉条目应省略。

### 新增子页面或入口

标题：`新增{页面名}`

正文：

- 管控端：`现在可以在{入口位置}进入{页面名}，用于{核心用途}。`
- 用户端：`你现在可以在{入口位置}找到{页面名}，用来{核心用途}。`

按钮：`去看看`

### 页面重新排布

标题：`{页面名}布局已更新`

正文：

- 管控端：`{关键区域}现在移动到{新位置}，常用操作可以从这里继续完成。`
- 用户端：`你常用的{关键区域}换到了{新位置}，现在可以从这里继续操作。`

按钮：`知道了`

### 功能位置变动

标题：`{功能名}已移至{新位置}`

正文：

- 管控端：`原{旧位置}中的{功能名}现在可以在{新位置}找到，已有数据和配置不受影响。`
- 用户端：`{功能名}换了位置，现在可以在{新位置}找到。`

按钮：`查看位置`

### 页面整合

标题：`{页面名}已整合`

正文：`原{页面 A}和{页面 B}已合并到{新页面}，可通过{切换方式}查看不同内容。`

按钮：`去查看`

### 页面拆分

标题：`{页面名}已拆分`

正文：`原{页面名}中的功能已拆分为{页面 A}和{页面 B}，请按任务选择入口。`

按钮：`查看说明`

### 页面入口下线

标题：`{入口名}即将下线`

正文：`{入口名}将在{时间}下线，请改用{替代入口或路径}。`

按钮：`查看新入口`

### 新增按钮或操作

标题：`新增{操作名}`

正文：

- 管控端：`现在可以在{位置}使用{操作名}，用于{操作结果或价值}。`
- 用户端：`你现在可以在{位置}使用{操作名}，{操作结果或价值}。`

按钮：`试试看`

### 新增表格列或字段

标题：`新增{字段名}`

正文：

- 管控端：`列表中新增{字段名}，可用于判断{字段含义或业务状态}。`
- 用户端：`这里多了一个“{字段名}”信息，方便你了解{字段含义}。`

按钮：`知道了`

### 新增筛选、排序或分组

标题：`新增{筛选维度}`

正文：

- 管控端：`现在可以按{筛选维度}查看内容，帮助你更快定位{目标对象}。`
- 用户端：`你现在可以按{筛选维度}筛选内容，更快找到想看的{目标对象}。`

按钮：`试试看`

### 名称或文案变更

标题：`{新名称}（原{旧名称}）`

正文：`{旧名称}已更名为{新名称}，{功能是否变化说明}。`

按钮：`知道了`

### 底层逻辑变更

标题：`{功能名}逻辑已更新`

正文：

- 管控端：`{功能名}现在按{新逻辑}处理，操作结果可能与旧版本不同。`
- 用户端：`{功能名}的处理方式有更新，结果可能和之前不一样。`

按钮：`查看详情`

### 规则、策略、计费或配额变更

标题：`{规则名}已更新`

正文：

- 管控端：`{变化内容}。如果继续按旧规则操作，可能会{失败结果或影响}。`
- 用户端：`{变化内容}。如果操作和以前不同，请按新的提示完成。`

按钮：`查看规则`

### 权限或账号体系变更

标题：`{权限或账号能力}已更新`

正文：

- 管控端：`{影响对象}的{登录、认证或权限范围}发生变化，请确认是否影响团队使用。`
- 用户端：`你的登录方式或可用范围有变化，请按页面提示继续使用。`

按钮：`查看影响`

### 合规或隐私变更

标题：`数据规则已更新`

正文：

- 管控端：`{数据处理、留存或导出规则}发生变化，请查看并确认相关说明。`
- 用户端：`与你的数据使用方式相关的说明有更新，请查看最新内容。`

按钮：`查看说明`

### 已知问题修复

标题：`{问题名}已修复`

正文：`此前{问题表现}的问题已修复，现在可以{恢复后的行为}。`

按钮：`知道了`

## 国际化占位

如果产品使用 i18n，不要直接写死中文，输出文案 key 和中文默认值：

```json
{
  "title_key": "updates.featureName.title",
  "title_default": "新增企业插件库",
  "body_key": "updates.featureName.body",
  "body_default": "现在可以在侧边栏进入企业插件库，统一管理插件分发。",
  "cta_key": "updates.featureName.cta",
  "cta_default": "去看看"
}
```
