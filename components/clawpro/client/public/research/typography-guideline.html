TYPOGRAPHY GUIDELINE

ClawPro 用户端 Typography 使用规范

Typography 是用户端文字的基础组件入口。它把字号、字重、行高、字体族和默认颜色 token 绑定到同一个语义组件中，让大家写页面时先选择“文字角色”，而不是临时拼 `text-sm`、`font-medium`、`text-gray-*`。

查看组件层级 查看使用规则

1. 为什么要用 Typography

目标不是增加一套复杂组件，而是减少页面里散落的文字样式，让所有新页面、新组件自然对齐同一套视觉标准。

Design Intent
1
按语义选组件标题、正文、辅助信息、数字、代码各有固定入口，减少同字号不同含义。
2
默认色由 token 提供不要再手写基础文字色，默认通过 `tone` 绑定 v2 色阶。
3
组件影响后续新增新增页面和业务组件优先使用 Typography，底层组件对齐其规格。
4
触达即同步改到旧页面时顺手迁移当前文件中明显的标题、正文、Meta、数字和代码。

2. 默认颜色 token

Typography 的默认颜色来自 `tone`。页面中基础文字不要再直接散落写 `text-gray-*` 或 `text-[#...]`。

4. 其他组件如何受 Typography 影响

业务组件应直接使用 Typography；底层 UI 组件不一定直接 import Typography，但内部文字规格必须映射到 Typography 层级。

推荐映射

新建或修改组件时先查这张表。

组件 / 场景推荐文字规格
Button / Tab / Segment itemBodyMedium 对应规格：14px / Medium / emphasis
Dialog / Sheet 标题PanelTitle
Card 标题CardTitle
表格表头MetaMedium
表格内容BodyText 或 InlineNumber
空状态说明MetaText tone="weak"
Badge / New / BetaTinyText 或 MetaMedium
统计卡数字StatNumber
ID / Token / 路径CodeText

使用示例

页面和业务组件中应优先这样写。

  TenantPageTitle,
  PanelTitle,
  CardTitle,
  BodyText,
  BodyMedium,
  MetaText,
  StatNumber,
  CodeText,

<TenantPageTitle>Agent 详情</TenantPageTitle>
<BodyText>这里是当前 Agent 的配置说明。</BodyText>

<StatNumber>128,000</StatNumber>
<CodeText>ins-g71c6vud</CodeText>

5. Do / Don't

不要机械替换所有 `text-sm` / `text-xs`，必须按语义判断；也不要继续新增 inline 字体族。

不要这样写
<h2 className="text-base font-semibold text-gray-900">
  模型使用汇总
</h2>

<p className="text-sm text-gray-600">
  这里是说明文字
</p>

<span
  className="text-2xl font-bold text-black"
  style={{ fontFamily: "DIN Next LT Pro" }}
>
  128,000
</span>
推荐这样写
<PanelTitle>模型使用汇总</PanelTitle>

<BodyText>
  这里是说明文字
</BodyText>

<StatNumber>128,000</StatNumber>

6. Vibe Coding 迁移组件建议

我们主要通过 AI / Vibe Coding 迁移现有组件，所以重点不是“全仓替换”，而是给 AI 清晰边界：一次只迁移一个组件或一个页面区块，只改文字表达，不改业务逻辑。

Vibe Migration
每次开工 Prompt

迁移任何组件前，先把这段发给 AI，确保它读取规范并限制改动范围。

我要迁移当前组件的文字样式到 Typography 规范。

请先读取：
1. `SKILL-GLOBAL-COMPONENTS.md`
2. `client/src/components/ui/Typography.tsx`
3. `client/public/research/typography-guideline.html`

要求：
- 只迁移当前文件 / 当前组件，不做全仓替换
- 按语义使用 `@/components/ui/Typography`
- 页面标题、模块标题、卡片标题、正文、Meta、数字、代码分别映射到对应 Typography 组件
- 不新增 `text-gray-*`、inline `fontFamily`、无规范来源的 `text-[xxpx]`
- 保持原有布局、交互和业务逻辑不变
- 如果是底层 UI 组件，不一定直接 import Typography，但文字规格必须对齐 Typography token
完成后自检 Prompt

改完后继续让 AI 自检，避免迁移 Typography 时误改逻辑或引入散落样式。

请检查本次 Typography 迁移：
1. 是否还新增了 `text-gray-*` 或 `text-[#...]`
2. 是否还新增了 inline `fontFamily`
3. 是否有无规范来源的 `text-[xxpx]`
4. 标题、正文、Meta、数字、代码是否按语义映射
5. 是否误改了布局、交互、状态逻辑
6. 当前文件是否有 lint / TypeScript 问题
1示范组件

先做一个小样板

先选一个共享组件做示范，让团队知道 AI 应该怎么迁移。

  • `components/agent/AgentCard.tsx`
  • `components/topnav/NotificationPanel.tsx`
  • 只改文字表达，不改布局、交互和业务逻辑
2共享组件

再迁移复用组件

共享组件适合小步提交，改一次可以影响多个页面。

  • `client/src/components/topnav/**`
  • `client/src/components/agent/**`
  • 状态、空状态、卡片、表格区块组件
3按区块拆

页面按区域迁移

大页面不要一次迁移完整文件，让 AI 只处理一个明确区块。

  • Header / Title 区
  • 卡片列表区 / 表格区 / 弹窗区
  • 空状态 / 错误状态 / 统计数字区
4触达同步

复杂页面渐进处理

复杂大页只在业务迭代触达时顺手同步，避免一次性重构。

  • `OpenClawDetail.tsx`、`ChatView.tsx`、`AgentChat.tsx`
  • 优先迁移标题、Meta、数字、ID、Token、路径
  • 聊天正文、Markdown 正文可暂时保留内容型排版

7. Vibe Coding 指引

如果同事通过 AI 辅助快速生成页面或组件，不要只说“注意字体规范”，而要明确要求 AI 读取规范、使用 Typography，并按语义检查文字角色。

Prompt Guide
推荐短 Prompt

适合放在任意用户端页面 / 业务组件需求末尾。

这是用户端页面 / 组件，请按 `SKILL-GLOBAL-COMPONENTS.md` 的 Typography 规范实现。

要求：
- 优先使用 `@/components/ui/Typography`
- 不要自行发明字号、字重和基础文字色
- 不要新增 inline `fontFamily`
- 页面标题、卡片标题、正文、Meta、数字、代码文字必须按语义映射到 Typography 组件
完整开工 Prompt

适合新页面、新模块或较复杂组件开发前使用。

你正在开发 ClawPro 用户端页面 / 组件。

开工前必须读取：
1. `SKILL-GLOBAL-COMPONENTS.md`
2. `client/src/components/ui/Typography.tsx`
3. `client/public/research/typography-guideline.html`

Typography 规则：
- 新增页面 / 业务组件必须优先使用 `@/components/ui/Typography`
- 基础文字色不手写，使用组件默认色或 `tone`
- 数字用 `StatNumber` / `InlineNumber`
- ID、Token、路径、命令用 `CodeText`
- 如果现有层级不满足，先说明原因，不要直接发明新样式
Vibe Coding 自检清单
  • 页面标题：是否使用 `TenantHeroTitle` / `TenantPageTitle`，而不是 `text-2xl font-bold`？
  • 模块与卡片：模块标题用 `SectionTitle` / `PanelTitle`，卡片对象名用 `CardTitle`。
  • 正文与说明：普通正文用 `BodyText`，Label / Tab / 按钮文字按 `BodyMedium` 规格。
  • 辅助信息：时间、ID、Tooltip、空状态、描述文字优先用 `MetaText` / `MetaMedium`。
  • 数字与代码：统计数字用 `StatNumber`，表格数字用 `InlineNumber`，Token / 路径 / 命令用 `CodeText`。
  • 禁止项：不要新增散落的 `text-gray-*`、任意 `text-[xxpx]`、inline `fontFamily`。
  • 底层组件：即使不直接 import Typography，内部文字也必须与 Typography token 对齐。

8. 给同事的开发检查清单

新增页面、新增组件、修改旧页面时，用下面清单快速判断是否符合 Typography 规范。

Checklist
  • ✓页面标题是否使用 `TenantHeroTitle` / `TenantPageTitle`，而不是自己拼 `text-2xl font-bold`？
  • ✓卡片标题、面板标题、正文、辅助说明是否分别映射到 `CardTitle`、`PanelTitle`、`BodyText`、`MetaText`？
  • ✓数字是否使用 `StatNumber` 或 `InlineNumber`，并具备 DIN 与 `tabular-nums`？
  • ✓ID、Token、路径、命令是否使用 `CodeText`，而不是普通 `text-xs`？
  • ✓是否避免了新增 `text-gray-*` / `text-[#...]` 来表达基础文字色？如需变色，是否优先使用 `tone`？
  • ✓是否避免了新增 inline `fontFamily`？英文 Badge 是否使用 `TinyText`？
  • ✓如果底层 UI 组件没有直接 import Typography，其内部文字规格是否仍与 Typography token 对齐？
  • ✓如果确实需要新增文字层级，是否先更新 `Typography.tsx` 与 `SKILL-GLOBAL-COMPONENTS.md`？
合入规则： Typography 已写入 `SKILL-GLOBAL-COMPONENTS.md`。用户端新增页面 / 新增业务组件必须优先使用 Typography；新增全局组件的文字规格必须先映射到 Typography 层级。组件样式如在 rebase 后被改，以 addietang 和 miekoyychen 的版本为准强制恢复；新增组件需经 addietang 和 miekoyychen 审核后才能合入基线。

源规范：`client/src/components/ui/Typography.tsx` 与 `SKILL-GLOBAL-COMPONENTS.md`。本页面用于设计评审、代码评审和新同事接入说明。
