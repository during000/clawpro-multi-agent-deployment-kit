五、优化建议

按照影响面从高到低排序，优先处理能减少后续设计和研发重复劳动的事项。

Suggestions
1. 建立用户端 Icon Token 表

把 12/14/16/20/32/40/48 的尺寸、容器、颜色、hover 规则写成组件或常量。后续设计替换时只需要说「替换 16px 操作 icon」或「替换 40px 技能身份图标」。

2. 抽离 Agent 专属渐变 SVG

当前「详细配置」「开始对话」是内联 SVG，且用了径向渐变。建议抽为命名组件，放在 components/agent/AgentIcons.tsx，避免卡片内重复与 gradient id 冲突。

3. 明确“技能字母图标”是否是最终形态

技能广场主视觉目前是字母色块，并非真实图标。若设计要改成技能图标，需要定义：卡片 40px、列表 36px、详情 48px，且需要兜底字母样式。

4. 统一数据类图标颜色语义

模型额度当前蓝/紫/橙可读，但输入和请求同蓝、输出和总量同紫，信息密度高时区分不够。建议使用固定语义：请求蓝、输入靛蓝、输出紫、总量蓝紫、配额橙红。

5. 补充 icon-only 按钮可访问名称

技能广场的刷新、卡片/列表切换、技能卡「+」下发等 icon-only 按钮应补 aria-label 或 title，Chrome 采样中部分 label 为空。

6. 清理未使用 icon import

技能广场存在部分导入但未在主流程使用的 icon。建议在下一次触达时顺手清理，降低设计盘点与研发维护噪音。

7. 状态图标保持“图标 + 文案”组合

我的 Agent 状态已经是 16px 状态图标 + 12px 文案的强识别组合，不建议改成单独颜色点；如设计替换，应一次性覆盖 8 种状态。

8. 公共导航 icon 不与 lucide 混用修改

TopNav 是 Figma 导出的 inline SVG，业务页多为 lucide。改导航时应进入 NavIcons.tsx，不要直接替换为 lucide，以免和设计稿形态不一致。

六、设计改 icon 的推荐路径

按模块改动，避免只改可见页面导致详情态、禁用态、弹窗态遗漏。

Change path
改顶部导航：
替换 components/topnav/NavIcons.tsx；保持 16px、currentColor、红点 4px。
改 Agent 卡片：
角色头像改 /assets/avatars/；状态改 StatusBadge.tsx；操作改 AgentCard.tsx 或抽 AgentIcons.tsx。
改技能主视觉：
先确定是否从「字母色块」升级为真实 icon；同步覆盖卡片、列表行、详情页三处尺寸。
改模型额度统计：
优先改 StatCard 的 icon 和 iconColor；配额卡单独覆盖 Zap + Info。
改文件树：
统一处理 Folder / FileText / Chevron / Eye / Code；注意弱化颜色，不抢正文内容。
改操作菜单：
以语义为单位替换：刷新、重启、重装、终端、移除、删除；保留危险/禁用色。
